# 设计文档：单 PR 总测试报告 + 测试人写死王杰

- 日期：2026-08-03
- 状态：已确认

## 目标

1. 每个 PR 只生成**一份总测试报告**，评测收尾合并生成并覆盖，无论有无 BUG 都上传到 PR。
2. 测试人写死为**王杰**（替换现有 Dengbiqiang）。

## 背景（现状）

- basictest 当前生成多份报告：整合测试报告.md、问题单.md、汇总报告、逐条用例说明等。
- 专业功能测试智能体（multica agent `9baece55`）指令第五节负责"报告挂到 PR + 指派测试人"，当前指派 Dengbiqiang 且仅在无 BUG 时执行。

## 改动

### A. basictest skill

1. **新增 `scripts/generate_total_report.py`**：
   - 输入：case-run 日期目录（含整合测试报告.md、问题单.md、正反用例集.md）
   - 输出：`总测试报告.md`（覆盖式），内容 = 测试统计 + 问题清单汇总 + 预期vs实际 + 结论
   - 固定命名 `{skill}_总测试报告.md`，重复运行覆盖同一文件，不新增
2. **SKILL.md 阶段七新增 7.5 章节**：
   - 收尾自动调用生成总报告，作为 PR 上传的唯一报告
   - 声明"一个 PR 一份总报告"规则

### B. 专业功能测试智能体指令

1. 第五节"报告挂载到 PR"：改为上传 `总测试报告.md`，无论有无 BUG 都执行上传
2. 指派测试人：`assignees: "王杰"`（写死，替换 Dengbiqiang）

## 数据流

```
评测收尾
  → generate_total_report.py 合并 → {skill}_总测试报告.md（覆盖）
  → 上传到 PR 评论（无论有无 BUG）
  → 指派 PR 测试人 = 王杰
```

## 边界

- 无 PR 链接时跳过上传/指派，在 issue 评论说明
- GitCode 附件不可用时评论内给出报告本地路径与归档地址
- 上传/指派失败不静默，评论说明原因
