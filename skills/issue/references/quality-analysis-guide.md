# Issue 内容质量分析

## Bug 类型

对 Bug 报告评估以下内容：

| 检查项 | 说明 |
|--------|------|
| 复现步骤 | 是否提供了完整的复现步骤？能否根据描述复现？ |
| 日志/截图/堆栈 | 是否有错误日志、截图或堆栈信息支撑？ |
| 环境信息 | 是否说明了操作系统、版本等环境？ |
| 预期 vs 实际 | 是否说明了预期行为和实际行为？ |

**评估结果：**
- 信息完整 → 确认是真实 bug，进入修复流程
- 缺少关键信息 → 标记 `need-info` 并追问具体缺失项

## Feature 类型

对功能需求评估以下内容：

| 检查项 | 说明 |
|--------|------|
| 需求描述 | 用户想要什么功能？描述的清晰度如何？ |
| 边界条件 | 是否有模糊表述（如"优化"、"更好"、"支持"等）？ |
| 使用场景 | 是否说明了使用场景和用户故事？ |
| 验收标准 | 是否有可衡量的完成标准？ |

**评估结果：**
- 需求清晰、边界明确 → 可直接进入方案设计
- 需求模糊、缺乏场景 → 标记 `need-info` 并追问具体场景和边界

## 分析结论输出

将分析结果输出到 Issue 分析结论中，例如：

```
内容质量：信息完整，确认是真实 bug
内容质量：需求清晰，边界明确
内容质量：缺少复现步骤，需追问用户补充
```
