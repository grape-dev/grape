# Issue 有效性检查

## 执行前提

仅当 Issue **没有标签**且**没有负责人**时，才需要进行有效性检查。
如果 Issue 已有标签或已分配负责人，说明已处理过，跳过此步骤。

## 检查流程

### 1. 是否已实现

用 API 获取最近 commit，搜索 commit message 是否匹配 Issue 标题：

```bash
GET /repos/{owner}/{repo}/commits?per_page=20
```

**匹配到相关 commit** → 回复并建议关闭：
> 该功能已在 [`{sha}`](链接) 中实现，建议关闭。
→ **跳过后续所有步骤**

### 2. 是否重复

用 API 搜索 open 状态的 Issue，检查标题/正文相似度：

```bash
GET /repos/{owner}/{repo}/issues?state=open&per_page=20
```

**找到重复** → 在重复 Issue 中评论：
> 与 [#N](链接) 重复，已在 #N 中跟进，关闭此 Issue。
→ **关闭并跳过后续所有步骤**

### 3. 描述是否清晰

判断条件（满足任一即视为描述不清晰）：
- 正文少于 30 字
- 无复现步骤（对 bug 类型）
- 无日志/截图（对 bug 类型）
- 无具体需求描述（对 feature 类型）

**描述不清晰**：
→ 标记 `need-info` 标签
→ 评论要求用户补充信息
→ **跳过分配步骤**，等待用户补充后重新触发

## 总结

| 检查项 | 通过则 | 不通过则 |
|--------|--------|---------|
| 是否已实现 | 继续下一步 | 回复建议关闭，跳过 |
| 是否重复 | 继续下一步 | 评论并关闭，跳过 |
| 描述是否清晰 | 进入分诊流程 | 标记 need-info，跳过分配 |
