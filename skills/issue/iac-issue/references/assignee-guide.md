# Assignee Guide

## Assignment Priority

1. CODEOWNERS match - If the issue matches a CODEOWNERS pattern, assign to that owner
2. Module expert - If no CODEOWNERS, match by module/area expertise
3. Team rotation - If no match, assign to team rotation assignee
4. Issue creator - If all above fail, assign back to issue creator with a note

## Multi-assignee Rules
- Complex issues may have multiple assignees
- Primary assignee is the main responsible person
- Secondary assignees are reviewers/consultants

## Unassign Conditions
- Issue closed/won't fix - Unassign all
- Assignee requests unassign - Must find replacement
- No activity for 14 days - May reassign
