# 博客 Spec 生成指南

## 执行前提

- 已判定为博客场景（见 `blog-scene-detection.md`）
- 可开发性分析已完成，评级为 `ready`
- VOD A2A context 中的「博客需求清单」已解析（如有）

## 输入来源

| 输入 | 来源 | 用途 |
|------|------|------|
| 博客需求清单 | VOD A2A context 中的 `requirement_summary` | 主题/风格/结构/配图/视频/长度/语调/标签 |
| Issue 正文 | GitCode API | 原始需求描述、参考链接 |
| Issue 评论 | GitCode API | 用户补充信息 |
| 博客系统地址 | 项目知识 `project-info/member/blog-config.yaml` 或 Issue 正文 | 发布目标 |
| AI 模型配置 | 项目知识 `project-info/member/ai-models.yaml` | 配图/视频生成的 API Key/URL/Model |
| blog_api.py | GitCode contents API | 确认博客系统可用接口 |

## 博客 Spec 模板

```markdown
# Spec: Issue #{number} — {博客标题}

> Generated by Blog Issue Agent | Developability: ready | {datetime}

## Objective
- **要生成什么**：一篇图文并茂的博客文章（含 AI 生成配图 + AI 生成视频）
- **主题**：{从需求清单提取}
- **风格**：{科技评测/轻松科普/营销推广/...}
- **目标读者**：{技术开发者/产品经理/普通用户/...}
- **成功标准**：博客成功发布到 {BLOG_HOST}，首页可见，含可播放视频和可显示配图

## 博客内容规格

### 文章结构
- 章节数：{N} 章节
- 章节标题：{从需求清单提取}
- 字数：{标准 ~1200字 / 深度 ~2000-2500字}
- 特殊元素：{参数对比表格/引用块/高亮块/...}

### 配图规格
- 数量：{N} 张
- 风格：{写实产品风/科技概念风/...}
- 生成方式：qwen-image API
- 封面图描述：{封面图画面要求}

### 视频规格
- 时长：{5} 秒
- 生成方式：Wan2.2-I2V-A14B API
- 画面描述：{视频画面构想}
- 旁白语调：{专业介绍/情感氛围/...}

### 发布目标
- 博客系统地址：{BLOG_HOST}
- 发布接口：POST /api/articles + POST /api/upload
- 标签 ID：{从 /api/lables 查询匹配}

## Technical Approach

### 生成流程
1. 撰写 HTML 文章正文（含 {N} 章节 + 特殊元素）
2. 调用 qwen-image 生成 {N} 张配图（含封面）
3. 调用 Wan2.2 生成 5 秒视频
4. 组织产物到 blog/{topic-slug}/ 目录
5. 提交 PR 到仓库 dev 分支

### 发布流程（SRE 执行）
1. 合并 PR
2. 从 blog/{topic-slug}/ 读取 index.html + 媒体文件
3. 上传媒体到博客服务器（POST /api/upload）
4. 替换 HTML 中的相对路径为上传 URL
5. 发布文章（POST /api/articles）

## Acceptance Criteria
- [ ] 文章含 {N} 章节，字数符合规格
- [ ] 配图 {N} 张，封面图存在
- [ ] 5 秒视频可播放
- [ ] PR 已创建，blog/{topic-slug}/ 目录结构完整
- [ ] SRE 发布后博客首页可见
- [ ] 文章详情页 http://{BLOG_HOST}/article/{id} 渲染正确

## Risks & Mitigations
| Risk | Impact | Mitigation |
|------|--------|------------|
| AI 模型 API 不可用 | High | 发布前 curl 验证 /health + API Key 有效性 |
| 图片/视频生成超时 | Med | 每张图 60s 超时，视频 120s 超时，失败重试 1 次 |
| 博客系统不可达 | High | Spec 生成前 curl /health 验证 |
| 产品外观与实物不符 | Med | 涉及具体产品时须先官网调研提取视觉特征 |
```

## 发布方式

### 作为 Issue 评论发布

```python
import json, urllib.request, os

TOKEN = os.environ["BOT_GITCODE_TOKEN"]
REPO = os.environ["REPO_FULL_NAME"]
ISSUE = os.environ["ISSUE_NUMBER"]

body = "[blog-issue Agent] 📋 博客 Spec Document\n\n" + spec_content

data = json.dumps({"body": body}).encode("utf-8")
req = urllib.request.Request(
    f"https://api.gitcode.com/api/v5/repos/{REPO}/issues/{ISSUE}/comments",
    data=data, method="POST"
)
req.add_header("PRIVATE-TOKEN", TOKEN)
req.add_header("Content-Type", "application/json")
with urllib.request.urlopen(req) as r:
    result = json.loads(r.read())
    comment_id = result.get("id")
```

格式要求：
- 评论 body 前缀固定为 `[blog-issue Agent]`
- Spec 内容使用完整 markdown 格式

### 打标签

```bash
curl -s -X PATCH -H "PRIVATE-TOKEN: $BOT_GITCODE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"labels": "{原有标签},spec-ready,blog-issue"}' \
  "https://api.gitcode.com/api/v5/repos/$REPO_FULL_NAME/issues/$ISSUE_NUMBER"
```

### 分配给机器人

```bash
curl -s -X PATCH -H "PRIVATE-TOKEN: $BOT_GITCODE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"assignee": "'"$BOT_USERNAME"'"}' \
  "https://api.gitcode.com/api/v5/repos/$REPO_FULL_NAME/issues/$ISSUE_NUMBER"
```

## A2A 通知 Coding Agent（博客专属）

```bash
curl -X POST {{SERVER_URL}}/api/a2a \
  -H "Authorization: Bearer $BOT_GITCODE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "agent": "coding",
    "payload": {
      "repository": "'"$REPO_FULL_NAME"'",
      "account": "'"$ACCOUNT"'",
      "issue_number": "'"$ISSUE_NUMBER"'",
      "context": "Issue #'"$ISSUE_NUMBER"' 博客需求已通过分析（评级: ready），博客 Spec 已发布。\n\n## 博客内容规格\n{spec.objective 摘要}\n\n## 文章结构\n{spec.structure 摘要}\n\n## 配图规格\n{spec.images 摘要}\n\n## 视频规格\n{spec.video 摘要}\n\n## 发布目标\n博客系统地址: {BLOG_HOST}\n发布接口: POST /api/articles + POST /api/upload\n\n请使用 ai-blog-generation 技能执行博客内容生成。完整 Spec 见 Issue 评论。"
    }
  }'
```

⚠️ **字段规则**：`issue_number` 必填；`pr_number` 有则填无则不填。

### context 构造规则

1. **评级**：ready
2. **指定技能**：明确告知 coding agent 使用 `ai-blog-generation` 技能
3. **博客规格摘要**：主题/结构/配图/视频/发布目标
4. **Spec 位置**：告知完整 Spec 在 Issue 评论中
5. **发布链路提示**：coding 完成后 A2A 给 sre（blog-publish 技能），非 qa

## Spec 版本管理

与 issue-advance 原始逻辑一致：用户提出修改 → 更新章节 → 版本号 +1 → 重新发布 → A2A 重新通知 coding。
