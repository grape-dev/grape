# 测试报告格式规范

## 固定标记（必须）

评论 body 开头独立行，后跟空行再写详细报告：

- 通过：`[QA Agent] ✅ 测试通过`
- 失败：`[QA Agent] 🔴 测试失败`

标记放在开头保证 merge 事件前置判断时 grep 稳定匹配。

## 通过报告模板

```
[QA Agent] ✅ 测试通过

## Skill 测试报告：{name} v{version}

## 功能验证
| 检查项 | 状态 | 证据 | 说明 |
|--------|------|------|------|
| API 调用 | ✅ 通过 | 返回 {N} 条数据 | 真实调用成功 |
| 参数校验 | ✅ 通过 | 缺参数时报错 | 校验逻辑生效 |
| 错误处理 | ✅ 通过 | 401 时返回提示 | 异常处理正常 |

## 规范检查
| 检查项 | 状态 | 说明 |
|--------|------|------|
| frontmatter | ✅ | name/description 完整 |
| 文件结构 | ✅ | SKILL.md/scripts/ 存在 |
| version 格式 | ✅ | x.y.z |

## 安全扫描
| 检查项 | 状态 | 说明 |
|--------|------|------|
| gitleaks | ✅ | 无硬编码密钥 |

## 结论
✅ 测试通过，可合并发布
```

## 失败报告模板

```
[QA Agent] 🔴 测试失败

## Skill 测试报告：{name} v{version}

## 功能验证
| 检查项 | 状态 | 证据 | 影响 | 修复建议 |
|--------|------|------|------|----------|
| API 调用 | 🔴 失败 | 退出码 1，报错 timeout | skill 不可用 | 检查 API 端点/超时设置 |

## 结论
🔴 测试失败，已 A2A 回退 Coding Agent 修复
- 失败原因：{摘要}
- 修复后 creator 重新 push → 自动重新测试
```

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| 检查项 | 是 | 验证的具体内容（API 调用/参数校验/错误处理等） |
| 状态 | 是 | ✅ 通过 / 🔴 失败 / ⚠️ 跳过 |
| 证据 | 是 | 实际执行结果（返回数据量/退出码/报错信息） |
| 影响 | 失败时必填 | 该项失败的影响（skill 不可用/校验缺失等） |
| 修复建议 | 失败时必填 | 具体可执行的修复动作 |
