# A2A 协作接口（/api/a2a）

> 对外公开，认证：`get_current_user_or_api_key`。Agent 间交办协作的核心端点（各技能最依赖：45 次引用）。
> scope（x-token-scope）：**dual**（三通道全放行；无效 token 走 `get_user_or_none` 软认证后交内部 bot 鉴权）。

## POST /api/a2a — 交办其他 Agent
> scope（x-token-scope）：**dual**（`grape_` API Key / JWT / `tk_` 会话 token 均可）
> CLI：`grape a2a handoff`（operation_id=`a2a_handoff`）。

请求头：`Authorization: Bearer <api_key>` + `Content-Type: application/json`

请求体：

```json
{
  "agent": "coding",
  "idempotency_key": "task-42:qa",
  "payload": {
    "repository": "owner/repo",
    "account": "owner/repo",
    "issue_number": "5",
    "pr_number": "",
    "context": "当前处理摘要"
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `agent` | string | ✅ | 目标 Agent：vod/issue/coding/qa/sre |
| `idempotency_key` | string | 否 | 幂等键（Issue #544）：由来源 task_id + 目标角色派生（如 `task-42:qa`），1-128 位 `[A-Za-z0-9_:.-]`；也可放 `payload.idempotency_key`（body 顶层优先）。同仓同键重复请求返回已有事件，不创建新事件 |
| `payload.repository` | string | ✅ | 仓库（owner/repo） |
| `payload.account` | string | ✅ | 账户 |
| `payload.issue_number` | string | ✅ | **必填**，严禁填 PR 编号 |
| `payload.pr_number` | string | 否 | 有则填 PR 编号，无则省略 |
| `payload.context` | string | ✅ | 接力说明（原始需求/分析结论/建议下一步） |

出参：

```json
{"status": "ok", "seq": 2048, "agent": "coding", "task_id": "t_xxx",
 "event": {"seq": 2048, "status": "running", "agent": "coding", "issue_id": "#5"}}
```

> Issue #1691：成功派发响应带 `event`（与实际建事件同口径），CLI 据此校验 `seq>0`
> 与下游派发状态；`status=failed` 或 `seq=0`（且无 `skipped`/`queued`）时调用方必须
> 显式报错，不得静默当作成功。

幂等命中（同键重复请求）时返回已有事件：

```json
{"status": "ok", "seq": 2048, "agent": "coding", "idempotent": true,
 "message": "duplicate idempotency_key, existing event returned",
 "event": {"seq": 2048, "status": "running", "agent": "coding", "issue_id": "#5", "created_at": "..."}}
```

处理异常且未建成事件时返回 500 + 请求指纹（事件表已留失败痕迹，可用核对接口查询）：

```json
{"code": 500, "message": "a2a processing failed: ...", "fingerprint": "9af3c2e18b0d47f6",
 "hint": "retry with the same idempotency_key, or verify via GET /api/a2a/status"}
```

## GET /api/a2a/status — 交接核对（Issue #544 L3）
> scope（x-token-scope）：**dual**（与 POST /api/a2a 同口径）

查询某次 A2A 交接是否已建事件（含失败留痕）。`idempotency_key` 非空按键精确查；
否则按请求指纹（`repository`+`issue_number`+`agent` 派生 sha256 前 16 位）查。

```
GET /api/a2a/status?repository=owner/repo&issue_number=5&agent=coding
GET /api/a2a/status?repository=owner/repo&issue_number=5&idempotency_key=task-42:qa
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `repository` | string | ✅ | 仓库（owner/repo） |
| `issue_number` | string | ✅ | Issue 编号（纯数字） |
| `agent` | string | 否 | 目标 Agent（指纹维度） |
| `idempotency_key` | string | 否 | 幂等键（精确查） |

出参：

```json
{"found": true, "repository": "owner/repo", "issue_number": "5", "agent": "coding",
 "events": [{"seq": 2048, "status": "running", "agent": "coding", "created_at": "...",
             "a2a_trace": false, "fingerprint": "9af3c2e18b0d47f6", "idempotency_key": "task-42:qa"}]}
```

返回：

| 码 | 场景 |
|----|------|
| 200 | 交办成功（seq 为新建事件编号） |
| 200 + skipped | sre 订阅去重跳过（`{"status":"ok","seq":0,"skipped":"sre_subscribed"}`） |
| 403 | token 无效 |
| 400 | `issue_number` 缺失/非法 |
| 400 | 仓库归属校验失败（Issue #671）：注册表（`managed_repos`）未命中时按 Git 平台可达性回退——`not found`（仓库不存在/拼写错误）、`no access`（仓库存在但无权限）、`not hosted`（无法判定/未托管，未认证调用方不触发回退，直接 `not hosted`）。回退放行后服务端自动幂等补录 `managed_repos`（自愈注册缺口），同一仓库与 git-repo 命令判定一致 |
| 409 | 目标 agent 不在当前 Issue 场景 nodes 内（`{"status":"skipped","skipped":"not_in_scene","scene":"<scene_id>","message":"...nodes=[...]"}`；Issue #568：节点集合与 `scenes detail` 同源 `get_pipeline_config`，两路口径一致；message 携带的 nodes 可作 scenes detail 不可用（404/403）时的权威兜底） |

> Issue #568：跨流水线移交（`payload.target_scene_id`/`target_node`）时校验目标场景存在
> （不存在 → 200 + `skipped: "target_scene_not_found"`），并将 issue 绑定场景刷新为
> 目标场景有效 ID（后续注入的 `GRAPE_SCENE_ID` 可经 `scenes detail` 查询且节点有效）。

## 约束

- `issue_number` 服务端强制校验，不得与 `pr_number` 混填。
- context 要简洁完整，让下游 Agent 无需重复分析。
- **超时/失败重试指引（Issue #544）**：客户端超时建议放宽至 60s+；超时后**先调
  `GET /api/a2a/status` 核对**（带同一幂等键/指纹），确认未建事件再带**同一幂等键**重试
  （≤2 次）；同键重试天然幂等，不会重复建事件。无键请求失败重试最多 3 次，
  仍失败在 Issue 评论标注需人工介入。
- **400 `repo not hosted` 降级路径（Issue #671，对齐后台反馈 319 口径）**：
  1. 先校正 `payload.repository` 的 owner/repo 拼写（二段格式、勿只传仓库名）；
  2. 确认该仓库已在平台托管（或 GitCode 上实际存在且服务端 token 可达——
     注册表未命中时服务端会自动做 GitCode 可达性回退并补录，正常无需人工处理）；
  3. 带同一幂等键重试 **≤3 次**；
  4. 仍失败 → 在当前 Issue 评论说明「A2A 交办失败（repo not hosted）+ 已重试次数」，
     并**人工交办**目标 Agent（在 Issue 中 @ 负责人或手工指派），不得静默跳过交办。

## POST /api/pipeline/handoff — 跨流水线移交（必填目标场景）
> scope（x-token-scope）：**dual**（`grape_` API Key / JWT / `tk_` 会话 token 均可）。
> CLI：`grape pipeline handoff`（operation_id=`pipeline_handoff`）。

语义与 `POST /api/a2a` 完全一致（同一实现、同一鉴权、同一幂等键），**唯一差异**：
`payload.target_scene_id` 必填，缺失或为空白 → 同步 400。这样命令名承诺的
「跨流水线」不会静默退化成当前场景内的普通派发；场内派发请继续用 `/api/a2a`。

请求体：

```json
{
  "agent": "coding",
  "idempotency_key": "task-42:coding",
  "payload": {
    "repository": "owner/repo",
    "issue_number": "5",
    "context": "接力说明",
    "target_scene_id": "custom-696e35a0",
    "target_node": "coding",
    "target_assignee": "",
    "carried_context": {}
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `agent` | string | ✅ | 目标 Agent：vod/issue/coding/qa/sre |
| `payload.repository` | string | ✅ | 仓库，必须 `owner/repo` 二段格式 |
| `payload.issue_number` | string | ✅ | 纯数字；不得与 PR 编号混填 |
| `payload.target_scene_id` | string | ✅ | **目标场景 ID**（缺省 → 400 `missing payload.target_scene_id`） |
| `payload.target_node` | string | 否 | 目标场景内起始节点，缺省 `vod` |
| `payload.carried_context` | object | 否 | 跨仓/跨场景携带的上下文（含 `target_issue_number` 回填依据） |
| `idempotency_key` | string | 否 | 同 `/api/a2a`：1-128 位 `[A-Za-z0-9_:.-]`，同仓同键幂等 |

出参：与 `/api/a2a` 相同（`{"status":"ok","seq":N,"agent":"..."}`）；目标场景不存在时
返回 200 + `skipped: "target_scene_not_found"`，场景节点不匹配时 200 + `skipped: "not_in_scene"`。

| 码 | 场景 |
|----|------|
| 200 | 移交成功（`seq` 为目标场景内新建事件编号） |
| 200 + skipped | 目标场景不存在 / 目标节点不在场景 nodes 内（语义同 `/api/a2a`） |
| 400 | 缺 `payload.target_scene_id`，或 `/api/a2a` 的既有参数校验失败（agent 白名单、单号纯数字、仓库二段格式） |
| 403 | token 无效 |
