## Technical Approach
新建 qa 技能，规则包/模板/脚本作为技能沉淀物，平台交互全走 grape CLI。
1. SKILL.md：frontmatter（name=architecture-guardian-3、agent_type=qa、description 首 57 字内含触发条件）；Prerequisites（`grape --version` ≥0.3.2 / `grape refresh` / `${VAR:+ok}` 校验）；环境变量表；平台交互表；收尾 `grape tasks complete`。
2. 规则包落地：24 条 + 4 级定义 + 级别→合入映射（BLOCKED→不建议合入；Critical→条件整改后可合入；Medium→报告标注需人工判断；Informational→不影响合入）+ 发现项证据契约。
3. 资产移植：以 3161 的 references/templates/scripts 为内容基线，以仓库 2.0（grape-architecture-guardian）的 runbook/平台范式为交互基线；全部路径改写为技能目录相对路径（bash 用 `SKILL_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"`，python 用 `Path(__file__).resolve().parent`），清除 `C:\Users\...` 类绝对路径。
4. 审查 runbook：Step0 前置+上下文 → Step1 拉材料（Issue 或 PR 的 diff/文件/commits，只读）→ Step2 跑 3 脚本取证 → Step3 逐条规则四态判定（符合/不符合/不适用/证据不足）→ Step4 汇总报告 → Step5 评论发布（`[QA Agent]` 前缀）→ Step6 `tasks complete`（+ A2A coding 整改）。
5. 自检：全文无未标源数字；A3（50tps）/A4（200ms）标注来源=明确业务要求（Issue #2403 原文），不得表述为实测或行业标准。
