# review 裁决模板（Architecture Gate）

> 用于 PR / 具体变更的门禁报告。body 以 `[QA Agent]` 开头；**一次 review 只给一个裁决**（三态：`APPROVED` / `APPROVED WITH CONDITIONS` / `BLOCKED`，语义与既有版本一致）。
> 检查面与最低证据：`references/gate-review.md` §2；阻断条件：同文件 §3。

## §1 首屏（不可调整顺序）

```
[QA Agent] 架构守护审查报告（PR #{N}｜head sha {sha8}｜base {branch}｜模式 review）

裁决：{APPROVED | APPROVED WITH CONDITIONS | BLOCKED}
四级统计：{N} BLOCKED / {N} Critical / {N} Medium / {N} Informational
需人工判断（Medium）：{编号 + 一句话影响；无则「无」}
阻断命中：{无 | 阻断条件 #x（说明）}
待决策清单：{Z} 条（缺测量的数字项）
```

## §2 APPROVED WITH CONDITIONS · 条件模板（四段齐备，缺段即无效）

```
条件 {i}（对应规则 {A14}｜检查项 {B-2}）
- 条件内容：{要改什么：文件/接口/配置 + 期望行为}（证据：{file:line}）
- 举证要求：{改完用什么证明：单测/契约测试/压测/演练 + 指标口径}
- 解除条件：{何种可观测状态即视为解除}
- 跟踪方式：{PR 评论 id / 后续 commit sha / 回归检查项编号}
```

反例（不成立，不得据此给条件通过）：「优化一下性能」「改完告诉我」「尽量」「后续关注」。

## §3 BLOCKED · 必附内容

| 命中 | 必须写清 |
|------|----------|
| 阻断条件 #1（BLOCKED 级规则不符合） | 规则编号（A5/A9/A10/A11/A12/A13/A14、B1/B3/B4、D1/D2 之一）+ `file:line` 或 `commit sha` + 故障场景 |
| 阻断条件 #2（阻断级失败模式无缓解） | 失败路径 + 缺失的缓解手段（超时/熔断/降级/隔离）+ 影响面（数据错误/不可用/泄露） |
| 阻断条件 #3（证据缺失无法判定） | 检查面名称 + `INSUFFICIENT DATA TO VERIFY` + **缺哪种测量或文档** + 建议测量方案 |

> 风格偏好、命名口味、无证据推测**不得**写进阻断理由；可整改的 `Critical` 走 §2 条件通过。

## §6 收尾

- `BLOCKED`/需整改且命中 `coding` 节点 → A2A `coding`（携带裁决 + 条件/缺陷清单 + 报告 comment id）。
- `APPROVED` 且需放行、命中 `sre` 节点 → A2A `sre`。
- 然后 `grape tasks complete`（`next_step`：`a2a_coding` / `a2a_sre` / `reply_comment`）。
