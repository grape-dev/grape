# Issue #600 Spec：重派成功后流水线卡片状态不重置

## 目标
agent 任务失败后重新派发成功，流水线卡片同步刷新为最新终态，失败态不再残留。

## 现状
- A2A / run_pipeline / onboarding 三条重派路径会把**原事件标记为 `failed`**（"原事件标记 failed"），重派成功后该失败事件永久留在 events 表。
- 流水线节点状态按 agent 取「最新事件」，但重派生成的新事件成功后，旧失败事件仍以 failed 终态残留：
  - Issue 详情 pipeline 的 `segments[]` 每事件一段，旧失败段永久显示失败；
  - 详情端点 `archive-first`（优先读已停写的 event.json 档案），与 `/pipeline` 端点 events-first 不一致，可能返回冻结的旧失败态；
  - 前端流水线页 / 任务详情流水线卡片仅进入页面时拉取一次，无轮询，重派成功后必须手动刷新。

## 期望
1. 重派后原事件标记为 `cancelled`（被新 seq 接管），不再是失败态；
2. Issue 详情 pipeline 与 `/pipeline` 端点同源（events 优先，archive 兜底）；
3. 前端重派成功后跳转新事件 seq；
4. 流水线页与任务详情流水线卡片定时静默刷新，状态变化才重渲染（不干扰搜索/滚动）。

## 验收
1. 失败任务重派成功后卡片显示成功（新事件终态），旧事件显示"已取消（已被重派接管）"；
2. 卡片状态与任务真实终态一致，无需手动刷新/重开页面；
3. 既有终态保护（failed 不被 completed 覆盖）不受影响。

优先级：P1。目标分支：weekly-08-mys。
