# Spec: Issue #252 — 需求 #1762 应该关联 issue 224 而非 PR 224

> Generated by Coding Agent | 2026-09-28

## 问题根因

当 issue 与 PR 共享相同编号（如 #224）时，系统无法区分实体类型：
1. `_extract_issue_id_from_text` 对 `/issues/224` 和 `/pulls/224` 均返回 `#224`，丢失实体类型信息
2. `resolve_pr_issue_id` 从 PR title/branch 提取编号时，可能将 PR 自身编号误当关联 Issue
3. `_group_events_by_issue` 按 `_num_from_issue_id` 分组，`#pr_224_...` 与 `#224` 都映射到 "224"
4. events 表无 `entity_type` 列，无法区分事件关联的是 issue 还是 PR

## 修正方案

### 核心思路：引入 entity_type 字段，按 (entity_type, number) 联合查找

| 改动 | 文件 | 说明 |
|------|------|------|
| 新增 `_extract_entity_type_from_text` | event_store.py | 从 URL 路径区分 issue/pull_request |
| events 表加 `entity_type` 列 | db_setup.py | DDL + 迁移 |
| `append_event` 增加 entity_type 参数 | event_store.py | 存储实体类型 |
| `resolve_pr_issue_id` 跳过 PR 自引用 | event_pipeline.py | 提取编号与 PR 自身编号相同且实体类型为 PR 时跳过 |
| `run_pipeline` 设置 entity_type | event_pipeline.py | PR 事件→pull_request，Issue 事件→issue |
| `_num_from_issue_id` 排除 #pr_ 前缀 | issues.py | PR 订阅事件不混入 issue 分组 |
| `_group_events_by_issue` 按 entity_type 过滤 | issues.py | issue 事件与 PR 事件不混组 |

## 向后兼容

- `entity_type` 列 DEFAULT ''：旧事件无 entity_type，按现有逻辑推断（空=issue）
- `_extract_issue_id_from_text` 签名不变，新增独立函数获取 entity_type
- 旧 `#pr_` 格式 issue_id 仍由 `_query_pr_subscription_events` 独立处理
