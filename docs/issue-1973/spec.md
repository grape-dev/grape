# Spec: Issue #1973 — A2A 派发门禁自锁与排队失效修复

> Generated by Coding Agent | 开发基线：weekly-mys

## Objective
同一 Issue 的调用方事件仍在 running 时，`grape a2a handoff` 不得把调用方自身事件
判为 downstream_running 而必然跳过；确存在真实下游阻塞时，`queue=true` 必须真正
落库排队并在阻塞解除后补派。

## Scope
1. `src/api/a2a_dispatch_guard.py::find_running_downstream` 新增 `exclude_seq`，
   按调用方自身事件 seq 精确排除；其余下游 running 仍拦截（#1770 防抖语义不退化）。
2. `src/api/routes/webhook.py` 门禁调用处透传调用方事件 seq；`downstream_running`
   + `queue=true` 时落 `status=queued` 事件行并记录真实阻塞前序，阻塞解除后由
   `event_pipeline.drain_queued_a2a` 补派。
3. 响应语义：未入队时不得返回 `status=ok + skipped + queued=false` 的误导组合，
   `downstream_running` 跳过响应改为显式 `status=not_queued` + `queueable` 字段。
4. 回归用例：自派发放行、queued 落库与 `queued_count` 递增、解除后补派、异源仍拦截。
5. 文档：grape-dev/grape-skills 的 qa Runbook Step 5 增补 `downstream_running` /
   `queued=false` 处置分支与唯一降级路径。

## Out of Scope
- 不新增库表/迁移，复用既有 `events.status='queued'` 与 `_a2a_queue` 结构。
- 不重写 #1948/PR #1181 平台侧方案，仅对齐并补齐本单增量。
- #1974（幂等去重与 force 可执行性）、#1863（契约命令组缺失）不合并处理。

## Acceptance
- 同 Issue 源事件 running 中派发下游放行，QA→coding 打回不再 skipped。
- 真实下游 running + `queue=true` 产生 queued 行，`a2a status queued_count` 递增，
  解除后完成补派。
- 异源下游 running 仍被拦截，#1770 防抖用例零回归。
- 新增回归用例覆盖「同 issue 源事件运行中派发下游」。
- qa Runbook Step 5 含对应处置说明。
