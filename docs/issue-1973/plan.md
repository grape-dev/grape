# Plan: Issue #1973 — A2A 派发门禁自锁与排队失效修复

> Generated by Coding Agent | 开发基线：weekly-mys

## 根因
- `find_running_downstream` 只按「同 Issue + 场景顺序在后 + running/dispatched」判定，
  签名无 `exclude_seq`，调用方自身 running 事件被误判为下游 running。
- `routes/webhook.py` 门禁命中后在事件落库前直接返回 `skipped=downstream_running`，
  `queue=true` 越不过门禁，既不落库也无补偿派发。
- `drain_queued_a2a` 按 agent 收窄，qa 前序 + coding 排队的跨 agent 场景取不到排队行。

## 方案
### A. 按调用方 seq 精确排除
- `find_running_downstream(..., exclude_seq=0)`：命中事件 seq 等于 `exclude_seq` 时跳过，
  其余判定逻辑不变。
- 调用方 seq 由 `_a2a_source_event_seq(_a2a_session_info)` 解析（会话 token 的
  `session_key` → `agent_tasks.event_seq`），门禁前解析一次，后续落库复用。

### C. 门禁命中 + queue=true → queued 落库自动补派
- 落 `status=queued` 行，`payload._a2a_queue.existing_seq` 指向真正阻塞的下游事件，
  `reason=downstream_running`，携带补派所需 `dispatch` 信息。
- 下游终态 → `drain_queued_a2a` 原子抢占并补派；入队后立即 `reconcile_queued_a2a`
  兜底「判定→落库」竞态窗口。
- `drain_queued_a2a` 不再按 agent 收窄，改按 issue 维度取 queued 行后以
  `_a2a_queue.existing_seq` 精确匹配，支持 qa→coding 跨 agent 补派。

### 不可入队语义
- `downstream_running` 且未声明 queue：响应 `status=not_queued`、`queued=false`、
  `queueable=true`、`action=retry_with_queue_true`，明确「未入队且未派发」，
  唯一恢复路径为 `queue=true` 或 `force=true`。

## 兼容与回归
- 无会话/bot token 通道：`_a2a_source_event_seq` 返回 0，等价旧语义，异源仍拦截。
- `queue=false` 保持 skip 留痕；#1770 时间窗/active 去重/storm 告警逻辑不改。
- 现有 #1667 同 agent 排队由 `existing_seq` 精确匹配保证，不受查询放宽影响。
