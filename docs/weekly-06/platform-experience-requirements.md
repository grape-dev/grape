## 需求 26：项目创建与工作空间进入的平台选择

**用户故事：** 作为同时绑定了 GitCode 和 GitHub 的用户，我希望在创建新项目和进入工作空间时能选择目标平台，以便我把项目创建到正确的平台上，并进入正确平台的工作空间。

**业务背景：**

当前系统在以下两个场景缺少平台选择：

1. **创建新项目：** 用户点击"新建项目"后，系统自动选择一个平台创建仓库，用户无法决定项目创建在 GitCode 还是 GitHub 上。如果用户同时绑定了两个平台，系统默认选 GitHub，但用户可能想把项目放在 GitCode 上。

2. **进入工作空间：** 用户点击"工作台"时，系统自动选择第一个可用仓库进入，不区分平台。用户绑定了两个平台后，想进入 GitHub 平台的工作空间，但系统可能跳到了 GitCode 的仓库。

**业务流程（创建新项目）：**

1. 用户在项目页点击"新建项目"
2. 系统展示创建表单，表单顶部显示平台选择区域
3. 平台选择区域展示用户已绑定的所有平台，每个平台一张卡片（平台品牌图标 + 平台名称），用户点选其中一个
4. 如果用户只绑定了一个平台，默认选中该平台，不显示平台选择区域
5. 用户填写项目名称、描述、可见性
6. 用户点击"创建"
7. 系统在用户选中的平台上创建仓库
8. 创建成功后，提示"项目已在 [平台名] 创建成功"，并刷新项目列表

**业务流程（进入工作空间）：**

1. 用户在项目页点击"工作台"
2. 系统检查用户已绑定的平台数量：
   - 只绑定一个平台 → 直接展示该平台下已托管的仓库列表，用户选择仓库进入工作台
   - 绑定多个平台 → 展示平台选择卡片（每个平台一张卡片，显示品牌图标、平台名称、该平台下已托管仓库数量），用户点选平台后展示该平台的仓库列表
3. 用户选择仓库后进入工作台

**业务规则：**

- 平台选择区域仅展示用户已绑定的平台，未绑定的平台不展示
- 只绑定一个平台时不显示平台选择，直接使用该平台
- 创建项目时必须选择平台，默认选中第一个绑定的平台
- 创建项目时平台选择后不可中途切换（切换会清空已填写的项目名称）
- 进入工作空间时的平台选择为一次性选择，不持久化（每次进入都让用户选）
- 平台选择卡片使用平台品牌图标，不使用 emoji 或文字缩写
- 创建项目成功后，提示文案中包含平台名称，让用户确认项目创建在了正确的平台
- 创建项目失败时，提示具体失败原因（如"仓库名称已存在""平台访问令牌已过期"等）

**验收标准：**

- 用户同时绑定两个平台时，点击"新建项目"后看到平台选择区域，有两个平台卡片可选
- 用户只绑定一个平台时，点击"新建项目"后不看到平台选择区域，直接填写项目信息
- 创建项目时选择 GitCode 平台，项目创建在 GitCode 上，提示"项目已在 GitCode 创建成功"
- 创建项目时选择 GitHub 平台，项目创建在 GitHub 上，提示"项目已在 GitHub 创建成功"
- 仓库名称在所选平台上已存在时，提示"该平台已存在同名仓库"
- 创建失败时提示具体失败原因
- 用户同时绑定两个平台时，点击"工作台"后看到平台选择卡片
- 用户只绑定一个平台时，点击"工作台"后直接展示该平台的仓库列表
- 进入工作空间的平台选择卡片显示每个平台下已托管仓库数量

**与现有需求的关系：**

- 扩展需求 17（未绑定第三方平台的用户引导）中"项目页按平台组织"的设计，补充创建项目和进入工作空间的平台选择
- 关联需求 5（账号绑定与解绑），平台选择依赖用户已绑定的平台列表

## 需求 27：平台绑定双模式（OAuth 授权 + 手动令牌）

**用户故事：** 作为需要绑定代码托管平台的用户，我希望除了 OAuth 跳转授权外，还能直接输入平台的访问令牌完成绑定，以便在 OAuth 回调地址无法配置或网络受限的环境下也能完成绑定。

**业务背景：**

当前平台绑定只支持 OAuth 跳转授权。用户点击"绑定 GitCode"后跳转到 GitCode 授权页面，授权后回调回来完成绑定。但存在以下问题：

1. **回调地址限制：** OAuth 授权需要一个公网可访问的回调地址，内网部署或本地开发环境下回调无法到达，用户无法完成绑定。
2. **网络受限：** 部分企业内网环境下，用户的浏览器无法直接访问 GitCode/GitHub 的授权页面，OAuth 跳转失败。
3. **用户习惯差异：** 部分开发者更习惯直接在平台生成访问令牌后粘贴到系统中，而不是走 OAuth 跳转流程（类似 Git 配置 personal access token 的习惯）。

**绑定模式设计：**

每个平台提供两种绑定方式，用户在绑定前可选择：

| 绑定模式 | 说明 | 适用场景 |
|---------|------|---------|
| OAuth 授权绑定 | 跳转到平台授权页面，授权后自动回调完成绑定 | 公网部署、回调地址可达 |
| 手动输入令牌 | 用户在平台生成访问令牌，粘贴到系统中完成绑定 | 内网部署、回调地址不可达、偏好手动操作 |

**业务流程（手动输入令牌绑定）：**

1. 用户在用户设置的"账号安全"页面看到第三方平台列表
2. 用户点击某平台的"绑定"按钮
3. 系统展示绑定方式选择：两个选项卡——"OAuth 授权"和"手动输入令牌"
4. 用户选择"手动输入令牌"
5. 系统展示令牌输入表单：
   - 令牌输入框
   - "如何获取令牌？"帮助链接，点击后展开获取步骤说明
   - 平台特定的获取指引（如 GitCode：前往 gitcode.com → 设置 → 私人令牌 → 新建令牌；GitHub：前往 github.com → Settings → Developer settings → Personal access tokens → 生成新令牌）
6. 用户在平台上生成令牌后，粘贴到输入框
7. 用户点击"确认绑定"
8. 系统验证令牌有效性：
   - 调用平台的用户信息接口，获取平台用户标识和用户名
   - 验证通过 → 写入绑定关系，加密存储令牌
   - 验证失败 → 在表单内显示错误原因（令牌无效/已过期/权限不足），不关闭表单
9. 绑定成功后，提示"[平台名] 绑定成功，现在可以管理该平台的仓库"，刷新页面显示已绑定状态

**业务流程（OAuth 授权绑定）：**

保持现有 OAuth 跳转绑定流程不变，但增加绑定方式选择入口：

1. 用户在用户设置的"账号安全"页面看到第三方平台列表
2. 用户点击某平台的"绑定"按钮
3. 系统展示绑定方式选择：两个选项卡——"OAuth 授权"和"手动输入令牌"
4. 用户选择"OAuth 授权"（默认选中）
5. 用户点击"前往授权"
6. 跳转到平台授权页面，授权后回调完成绑定

**业务规则：**

- 两种绑定方式达到相同的效果：绑定后可管理该平台的仓库、可用该平台快捷登录
- 同一平台的同一账号，无论通过哪种方式绑定，都关联到同一个 Grape 账号
- 同一平台的同一第三方账号只能绑定一个 Grape 账号（手动令牌绑定时也校验）
- 手动输入的令牌验证通过后加密存储，与 OAuth 令牌存储方式一致
- 手动令牌验证失败时不关闭表单，在表单内显示具体错误原因，用户可修改后重试
- 令牌获取指引根据平台不同展示不同内容，帮助用户快速找到生成令牌的入口
- 如果用户已通过 OAuth 绑定了某平台，再用手动令牌绑定同一平台时，提示"该平台已绑定，是否更新令牌？"，确认后更新令牌
- 如果用户已通过手动令牌绑定某平台，再走 OAuth 绑定同一平台时，OAuth 授权完成后自动更新绑定信息
- 手动令牌绑定成功后，和 OAuth 绑定一样，清除仓库缓存，下次进入工作台时拉取新平台的仓库

**验收标准：**

- 用户点击"绑定"后看到两种绑定方式可选（OAuth 授权 / 手动输入令牌）
- 选择"手动输入令牌"后看到令牌输入框和"如何获取令牌？"帮助链接
- 点击"如何获取令牌？"后展开对应平台的获取步骤说明
- 输入无效令牌后点击"确认绑定"，表单内显示错误原因，表单不关闭
- 输入有效令牌后点击"确认绑定"，提示"[平台名] 绑定成功，现在可以管理该平台的仓库"
- 绑定成功后页面刷新，该平台显示"已绑定"状态
- 通过手动令牌绑定的平台，和通过 OAuth 绑定的平台行为一致（仓库列表正常展示、可创建项目、可进入工作台）
- 已通过 OAuth 绑定的平台，再用手动令牌绑定时，提示"该平台已绑定，是否更新令牌？"
- 手动令牌绑定成功后，仓库缓存被清除，进入工作台时能拉到新平台的仓库
- 令牌获取指引对不同平台展示不同内容

**与现有需求的关系：**

- 扩展需求 5（账号绑定与解绑），增加手动令牌绑定模式
- 关联需求 6（账号体系独立解耦），手动令牌和 OAuth 令牌存储方式一致
- 关联需求 15（独立用户中心），绑定入口在用户设置的"账号安全"子页面

## 需求 28：平台品牌视觉统一

**用户故事：** 作为 Grape 用户，我希望在系统的所有页面中看到正确的平台品牌图标，以便一眼区分 GitCode 和 GitHub，不用靠文字或 emoji 猜测。

**业务背景：**

当前系统中平台图标的展示不一致：

1. 项目卡片上用了正确的品牌 SVG 图标（GitHub 猫头鹰 logo、GitCode 字母 G logo）
2. 新手引导页的平台绑定卡片用了 emoji（🐙 代表 GitHub、🟠 代表 GitCode），不是品牌图标
3. 项目页平台切换栏用了 emoji
4. 用户设置中第三方账号列表没有平台图标
5. 项目页"新建项目"卡片没有平台图标

emoji 表示不专业且不准确——🐙 不是 GitHub 的品牌标识，🟠 不是 GitCode 的品牌标识。用户在系统的不同位置看到不同风格的图标，视觉不统一。

**业务规则：**

- 所有展示平台名称或平台标识的位置，统一使用平台品牌图标（SVG 矢量图）
- GitCode 品牌图标：GitCode 官方 logo（橙色字母 G 样式）
- GitHub 品牌图标：GitHub 官方 logo（猫头鹰剪影）
- 品牌图标支持跟随当前主题色变化（深色/浅色模式）
- 品牌图标的尺寸根据使用场景调整（列表行 14px、卡片 24px、大卡片 36px）
- 不使用 emoji 或文字缩写替代品牌图标
- 系统中所有涉及平台标识的位置统一调用同一套图标渲染逻辑

**需要统一图标的位置：**

| 位置 | 当前 | 改为 |
|------|------|------|
| 项目卡片平台标识 | 品牌 SVG（已正确） | 保持 |
| 项目页平台切换栏 | emoji（🟠/🐙） | 品牌 SVG |
| 新手引导页平台绑定卡片 | emoji（🟠/🐙） | 品牌 SVG |
| 新建项目弹窗平台选择卡片 | 无图标 | 品牌 SVG |
| 工作空间平台选择卡片 | 无图标 | 品牌 SVG |
| 用户设置第三方账号列表 | 无图标 | 品牌 SVG |
| 用户头像下拉菜单平台名称 | 无图标 | 品牌 SVG |

**验收标准：**

- 项目页平台切换栏的每个平台选项前显示对应品牌图标
- 新手引导页的平台绑定卡片显示对应品牌图标
- 新建项目弹窗的平台选择卡片显示对应品牌图标
- 工作空间平台选择卡片显示对应品牌图标
- 用户设置第三方账号列表每行显示对应品牌图标
- 所有位置的品牌图标风格一致，不是有的用 emoji 有的用 SVG
- 深色模式下品牌图标清晰可见
- 浅色模式下品牌图标清晰可见

**与现有需求的关系：**

- 扩展需求 17（未绑定第三方平台的用户引导），新手引导页平台卡片图标
- 扩展需求 15（独立用户中心），用户设置中第三方账号列表图标
- 关联需求 26（项目创建与工作空间进入的平台选择），新建项目弹窗和工作空间平台选择的图标

## 需求 29：用户设置页面重组

**用户故事：** 作为 Grape 用户，我希望和"我"个人相关的所有设置都能在一个地方找到，工作台相关的配置在另一个地方，以便我管理个人账号时不用在工作台设置和用户中心之间来回切换。

**业务背景：**

当前系统有两个设置入口，职责划分不清晰：

1. **用户中心**（侧边栏隐藏视图）：个人资料、账号安全（密码/邮箱/第三方绑定）、API Keys、危险区域（注销）
2. **通用设置**（侧边栏内嵌视图）：凭据（VCS Token + 华为云 AK/SK）、通知、外观（主题/语言）

问题：
- VCS 访问令牌（GitCode Token / GitHub Token）在"通用设置 > 凭据"里，但它实际上是用户个人的平台凭据，和"用户中心 > 账号安全 > 第三方账号绑定"是同一件事的不同入口——用户在用户中心用 OAuth 绑定了 GitHub，又要到通用设置里手动输入 GitHub Token，两个入口管理同一个东西，容易冲突
- 外观设置（主题/语言）是用户个人偏好，和项目凭据混在一起不合理
- "用户中心"这个名字不像设置页面——业界主流产品（GitHub、GitLab、Vercel、Linear）都叫 Settings
- 用户想修改主题时要去"通用设置"，想修改密码时要去"用户中心"，两个入口分散

**页面改名：**

"用户中心"改为"用户设置"。理由：
- "用户中心"暗示是一个概览/首页，但实际功能是设置
- "用户设置"直接表明页面职责，和业界主流产品一致
- 侧边栏分组名从"用户中心"改为"用户设置"

**设置项重组：**

将和用户个人直接相关的设置从"通用设置"移到"用户设置"：

| 设置项 | 现位置 | 移到 | 理由 |
|--------|--------|------|------|
| 平台访问令牌（GitCode/GitHub Token） | 通用设置 > 凭据 | 用户设置 > 账号安全 > 第三方账号 | 和 OAuth 绑定是同一件事，统一管理 |
| 外观（主题/语言） | 通用设置 > 外观 | 用户设置 > 外观 | 个人偏好，非项目级配置 |
| 华为云 AK/SK | 通用设置 > 凭据 | 用户设置 > 凭据 tab | 用户级凭据，独立 tab 扩展性好 |
| 通知偏好 | 通用设置 > 通知 | 移除 | 纯静态占位无功能 |

**重组后的页面结构：**

用户设置（6 个 tab）：
- 个人资料（用户名、邮箱、昵称）
- 安全（密码管理、邮箱管理、第三方平台绑定——OAuth + 手动令牌）
- 凭据（华为云 AK/SK，未来扩展其他云平台凭据）
- 外观（主题切换、语言切换）
- API Keys（创建/查看/撤销）
- 危险区域（注销账号）

通用设置已移除，侧边栏只保留"仓库设置"（Bot Token + 解除托管）。

**业务规则：**

- "用户中心"全部文案改为"用户设置"，包括侧边栏分组名、头像下拉菜单、引导文案
- 平台访问令牌管理从"通用设置 > 凭据"移到"用户设置 > 安全"的第三方账号区域，和需求 27 的绑定双模式统一
- 华为云 AK/SK 从"通用设置 > 凭据"迁移到"用户设置 > 凭据"独立 tab
- 外观设置从"通用设置"移到"用户设置 > 外观" tab
- 通知 tab 移除（原通用设置中的通知为纯静态占位，无后端 API 无保存功能）
- 通用设置页面移除，侧边栏"设置"分组只保留"仓库设置"
- 认证（security tab）和授权（credentials tab）分离，职责清晰
- 旧的用户中心链接自动跳转到用户设置，兼容历史书签

**侧边栏调整：**

| 位置 | 改前 | 改后 |
|------|------|------|
| 侧边栏分组标题 | 用户中心 | 用户设置 |
| 头像下拉菜单 | 个人资料 / 账号安全 / 用户中心 | 个人资料 / 账号安全 / 用户设置 |
| 新手引导页文案 | 前往用户中心 | 前往用户设置 |
| OAuth 补全提示 | 去设置 | 去用户设置 |
| 绑定引导卡片 | 账号设置 | 用户设置 |
| 侧边栏"设置"分组 | 通用设置 + 仓库设置 | 仓库设置 |

**验收标准：**

- 侧边栏分组标题显示"用户设置"（中）/ "User Settings"（英）
- 头像下拉菜单显示"个人资料""账号安全""用户设置"
- 用户设置页面包含六个标签页：个人资料、安全、凭据、外观、API Keys、危险区域
- 用户设置的"安全"标签页中，第三方账号区域展示每个平台的绑定状态，已绑定的可解绑，未绑定的可选择 OAuth 或手动令牌绑定
- 用户设置的"凭据"标签页展示华为云 AK/SK 输入框，可保存和切换明文/密文
- 用户设置的"外观"标签页可切换主题和语言
- 通用设置页面已移除，侧边栏不显示"通用设置"入口

## 需求 30：绑定与解绑体验优化

**用户故事：** 作为在用户设置中绑定或解绑平台的用户，我希望每一步操作都有清晰的反馈——成功时明确告知完成了什么、接下来能做什么，失败时明确告知原因和解决办法——以便我不会在操作后疑惑"到底成功了没有"或"为什么失败了"。

**业务背景：**

当前绑定/解绑的反馈（需求 25 已覆盖基本成功提示）存在以下不足：

1. **绑定成功提示太简短：** 只显示"绑定成功""可用该平台快捷登录"，没有告诉用户"现在可以创建该平台的项目了""该平台的仓库已出现在项目列表中"等下一步指引。
2. **绑定失败原因不清晰：** OAuth 绑定失败只显示"绑定失败"+ 回调返回的错误码，用户不理解"invalid_state""access_denied"等含义。手动令牌绑定失败只显示"令牌无效"，不区分"令牌格式错误""令牌已过期""令牌权限不足"。
3. **解绑成功缺少后续影响说明：** 只显示"已解绑""该平台登录已失效"，没有告知"该平台下的 N 个仓库已不再可用""如需重新使用请重新绑定"。
4. **操作过程中缺少加载状态：** 点击"确认绑定"后到返回结果期间，按钮没有 loading 状态，用户不知道是否在处理中，可能重复点击。

**绑定成功的反馈设计：**

| 绑定方式 | 成功提示 | 后续指引 |
|---------|---------|---------|
| OAuth 绑定 | "[平台名] 绑定成功" | "现在可以在项目页管理该平台的仓库，可用该平台快捷登录" |
| 手动令牌绑定 | "[平台名] 绑定成功" | "现在可以在项目页管理该平台的仓库" |

**绑定失败的反馈设计：**

| 失败场景 | 失败提示 | 解决办法指引 |
|---------|---------|------------|
| OAuth 授权被用户取消 | "授权已取消，绑定未完成" | "您可以重新点击绑定，或选择手动输入令牌" |
| OAuth 回调状态异常 | "授权回调异常，请重新绑定" | "如多次失败，可尝试手动输入令牌方式绑定" |
| OAuth 平台返回错误 | "平台授权失败：[原因翻译]" | "请稍后重试，或联系管理员" |
| 手动令牌格式错误 | "令牌格式不正确" | "请检查令牌是否完整复制，参考上方获取步骤" |
| 手动令牌已过期 | "令牌已过期" | "请在 [平台] 重新生成令牌后粘贴" |
| 手动令牌权限不足 | "令牌权限不足" | "请确保令牌包含仓库读写权限，参考上方获取步骤" |
| 手动令牌已被其他账号绑定 | "该平台账号已被其他 Grape 账号绑定" | "请先在另一个 Grape 账号中解绑该平台" |
| 网络错误 | "网络连接失败" | "请检查网络后重试" |

**解绑成功的反馈设计：**

| 操作 | 成功提示 | 后续影响说明 |
|------|---------|------------|
| 解绑（无活跃仓库） | "[平台名] 已解绑" | "该平台登录已失效，该平台下的仓库不再可用" |
| 解绑（有活跃仓库） | "[平台名] 已解绑" | "该平台登录已失效，N 个仓库已不再可用。如需恢复请重新绑定" |

**解绑失败的反馈设计：**

| 失败场景 | 失败提示 | 解决办法指引 |
|---------|---------|------------|
| 最后一种登录方式 | "至少保留一种登录方式" | "请先设置 Grape 密码后再解绑" |
| 系统错误 | "解绑失败，请稍后重试" | "如持续失败请联系管理员" |

**操作过程中的状态反馈：**

- 点击"确认绑定"后，按钮变为加载状态（禁用 + 旋转图标），防止重复点击
- 点击"确认解绑"后，按钮变为加载状态
- OAuth 跳转前显示"正在跳转到 [平台名] 授权页面..."
- 操作完成后加载状态消失，显示结果提示

**业务规则：**

- 所有绑定/解绑操作完成后必须显示明确的成功或失败反馈
- 成功反馈包含"完成了什么"+"接下来能做什么/发生了什么变化"
- 失败反馈包含"失败原因"+"如何解决"，用用户能理解的语言描述（不显示技术错误码）
- 操作过程中按钮显示加载状态，防止重复操作
- 失败时不关闭当前操作界面（弹窗/表单），让用户可以修改后重试
- 成功后关闭操作界面并刷新页面数据
- 解绑成功后如有受影响的仓库，提示中包含受影响仓库数量

**验收标准：**

- OAuth 绑定成功后提示"[平台名] 绑定成功" + "现在可以在项目页管理该平台的仓库，可用该平台快捷登录"
- 手动令牌绑定成功后提示"[平台名] 绑定成功" + "现在可以在项目页管理该平台的仓库"
- 手动令牌绑定失败时在表单内显示具体原因（格式错误/已过期/权限不足/已被绑定），不关闭表单
- OAuth 授权被用户取消后提示"授权已取消，绑定未完成" + "您可以重新点击绑定，或选择手动输入令牌"
- 解绑成功后提示"[平台名] 已解绑" + "该平台登录已失效，该平台下的仓库不再可用"
- 解绑有活跃仓库的平台成功后提示中包含受影响仓库数量
- 最后一种登录方式不可解绑时提示"至少保留一种登录方式" + "请先设置 Grape 密码后再解绑"
- 点击"确认绑定"后按钮变为加载状态，不可重复点击
- 操作失败时不关闭当前操作界面

**与现有需求的关系：**

- 扩展需求 25（敏感操作反馈），补充绑定/解绑的详细反馈规则
- 关联需求 5（账号绑定与解绑），绑定/解绑流程中的反馈
- 关联需求 27（平台绑定双模式），手动令牌绑定的失败反馈
