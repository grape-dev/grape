# 方案：帮助中心移除「系统自动编号」，文档手工编号为唯一正体（方案 B）

> 状态：技术方案（2026-10-11）｜分支：weekly-06-lyz
> 动机：`help_page_gen` 为左侧目录（`.dno`）与正文小节（`.sno` / `doc.no.sub`）分配**系统自动编号**，与 `help/usage/*.md` H1 里**手写序号**（`# 2. 快速上手` … `# 10. 常见问题`）重复；且两套来源靠人肉对齐，会漂移（可见例：`overview` 手工无号但系统给 "1"）。　选择 **方案 B**：**移除系统编号，文档自身手写编号作为唯一正体**——界面字体/对齐更统一、无性能影响、后续改文档即所见即所得（有误直接改 md）。
> 参考：`docs/weekly-06` 关联 issue 291「编号冗余」。

---

## 1. 现状（代码定位 2026-10-11）

| 编号层 | 生成位置 | 展示位置 |
|--------|----------|----------|
| 文档号 | `help_page_gen.py assign_doc_numbers`（L417-431）：按 `USAGE_ORDER` 顺序 `no=1..N`；api README 标 `is_overview` | 侧栏 `.dno`（L187） |
| 小节号 | `assign_toc_numbers`（L434-449）：`{doc.no}.{层级序号}`（如 `3.1`） | 侧栏子项 `.sno`（L174） |
| 手工 H1 号 | `help/usage/*.md` 标题 `# N. 标题` | 正文 H1 |

> 两套并存：侧栏与正文同显序号 → 冗余；`overview` 手工无号 vs 系统给 1 → 错位。

## 2. 方案设计（只移除"系统编号"，保留"手工编号"）

### 2.1 生成侧：不再计算/分配系统编号

`src/help_page_gen.py`：
- `_section_data`（L511-512）与 `_reference_data`（L530-531）移除对 `assign_doc_numbers` / `assign_toc_numbers` 的调用；
- `assign_doc_numbers`：改名为/收敛为 `mark_overview`——`api` 的 `README` 仍置 `is_overview=True`（保留"总览"徽章，非编号），其余**均不设 `no`**；
- `assign_toc_numbers`：**整体删除**（小节不再生成 `3.1` 序号）。

### 2.2 展示侧：侧栏不再渲染编号

`_JS_APP`（help_page_gen.py 内嵌 JS）：
- `sideList` L187：删除 `(d.no ? '<span class="dno">'+...` 分支（保留 `is_overview` 的"总览"徽章 `.dov`）；
- `subNav` L174：删除 `(r.no ? '<span class="sno">'...` 分支（小节仅显示标题、缩进表达层级）；
- CSS：删除 `.dno`（L101-102）与 `.sno`（L110）两条规则（保留 `.dov` 总览徽章样式）。

### 2.3 语义说明（改后）

- **唯一正体 = 文档 H1 手写编号**：想调整顺序/编号，直接改 `help/usage/*.md` 标题（所见即所得，重启/启动自动重建 `help.html`）；
- **侧栏仍是入口列表**：顺序由 `USAGE_ORDER`（帮助中心入口顺序）决定，但**不再显示数字**，避免与正文 H1 数字重复/错位；
- API 文档：同样去掉系统编号；`README` 保留"总览"徽章。

## 6. 配套：help/ 文档标题与编号格式统一（P2，与 B 一并进行）

> 盘点（2026-10-11，`help/` 全量标题）：当前格式**不统一**，需一并规范化。

### 6.1 现状盘点（不一致清单）

| 范围 | 现况 | 问题 |
|------|------|------|
| usage H1 | `# 2. 快速上手`…`# 10. 常见问题 (FAQ)` 带号；`overview.md` 无号 | 基本统一，但靠人肉维护（顺序=USAGE_ORDER） |
| usage H2 | 混合三种：`## 2.1 登录与仓库选择`（数字层级号）、`## 一、注入链路概览`（中文序号）、`## VOD Agent — 需求分析` / faq/overview 无 `##` | **格式不统一**；且 `skills.md` H1=`6` 而 H2=`5.1 官方技能` 已错位 |
| api H1 | 无编号（靠文件名 `00-`…`16-` 排序） | 可保留（排序重心在文件名） |
| api H2 | 混用：端点式 `## GET /api/… — 描述` 为主，另见 `## 读取（list/stats/detail）` `## 概念速览` `## 凭据 Credentials` `## 机器健康度（admin）` `## 全局约定…` 等章节式 | 端点小节与引导小节混用、措辞不一 |
| reference | H1 无号；H2 `## 一、统一事件类型…` | 中文序号与 usage H2 风格不齐 |

### 6.2 统一标准（方案 B 语义：文档自编号为唯一正体 → 定义"标准格式"）

1. **usage H1**：统一 `# N. 标题`（半角数字 + 半角 `.` + 空格）；`overview.md` 恒无号（总览），与系统"总览"徽章语义一致。
2. **usage H2**：**统一去层级/中文序号，纯标题**（删除手写 `2.1 / 4.1 / 一、` 等）——既然 B 已移除系统生成的 `.sno` 小节号，正文不再保留第三套编号；`skills` 的 `5.1` 错位随之消失。
3. **api H1**：维持无编号（排序依赖文件名 `NN-*.md`）；README 保持"总览"徽章。
4. **api H2**：统一为两型——端点小节：`## <METHOD> /path — 描述`；引导小节固定措辞：`## 概述` / `## 通用约定` / `## 认证方式` / `## 概念` 等（去除 `读取（…）`、`机器健康度（admin）`、`凭据 Credentials` 等随意标题，统一中文或中英对照）。
5. **reference**：H1 无号；H2 去 `一、` 前缀（纯标题）。

### 6.3 改动清单（概要）

| 文件范围 | 动作 |
|----------|------|
| `help/usage/*.md`（10 篇） | H2 去层级/中文序号：`2.1`→`登录与仓库选择`、`一、`→纯标题、`7.1 运维概览`→`运维概览` 等；H1 保留（overview 无号） |
| `help/api/*.md`（17 篇） | H2 端点小节保持 `METHOD /path — 描述`；改引导小节为固定措辞（约 7 处：07/10/11/13/14/16/README） |
| `help/reference/event-mapping.md` | H2 去 `一、` 前缀 |
| `help_page_gen.py` | 无额外改动（标准是文档级约束）；可选在 `_collect_toc` 对 `一、` 等做渲染归一，非必须 |

## 7. 落档修订说明

- 采用**方案 B**：保留文档手写 H1 编号为唯一正体；移除系统（侧栏+小节）自动编号。
- **P2 配套**：同步统一 `help/` 全量文档标题/编号格式（§6）——usage H2 去层级号、api H2 端点/引导措辞统一、ref H2 去中文序号；与 B 一并进行，一次上线。
- 不迁移既有 `# N.` 保留范围：usage H1 的 `# N. 标题` 保留并作为标准格式；overview 恒无号。
