## 问题 3（P1）：OAuth 用户设置密码流程缺乏上下文引导

### 是什么

用户通过 GitCode OAuth 登录后，页面顶部出现黄色提示条"为了账号安全，建议设置 Grape 密码和绑定邮箱"。点击"去用户设置"进入账号安全页，点"设置密码"后弹出模态框，标题仅"设置密码"，直接要求发送验证码 → 输入验证码 + 新密码 + 确认新密码。

用户通过 OAuth 进来，从来没有 Grape 密码。看到"设置密码"不知道该输入什么密码——是 GitCode 密码？还是什么？模态框没有说明这是"设置一个全新的 Grape 账号密码"。

### 影响

1. 用户不知道该输入什么密码——"设置密码"文案对 OAuth 用户有歧义
2. 用户不理解为什么要设置——缺少上下文（补充登录方式，不依赖第三方平台）
3. 用户不知道设置后能做什么——没有告知"设置后可用邮箱/用户名+密码登录"

### 触发条件

OAuth 用户首次进入设置密码流程时必定出现。

### 涉及文件

- `src/api/static/js/pages/account.js` 第 301-317 行（设置密码模态框 UI，无任何说明文案）
- `src/api/static/js/app.js` 第 838-879 行（OAuth 登录后安全提示条）
- `src/api/static/locales/zh/app.json` 第 181 行（提示文案）

### 根因

模态框纯功能导向，缺少面向 OAuth 用户的上下文引导。模态框标题仅"设置密码"，没有说明这是创建全新 Grape 密码、为什么要设置、设置后可做什么。

## 问题 4（P1）：设置密码的前置条件（邮箱）未在 UI 层拦截

### 是什么

设置密码需要邮箱验证码（后端 `grape_auth.py` 第 530-531 行，无邮箱返回 400）。但前端"设置密码"模态框不检查邮箱状态，无邮箱用户看到"验证码将发送到您的邮箱"提示 + "发送验证码"按钮，点击后后端报 400。

### 影响

- 无邮箱用户点"设置密码"→ 模态框弹出 → 显示"验证码将发送到您的邮箱"（但用户没有邮箱）→ 点"发送验证码"→ 后端 400 "请先绑定邮箱"→ toast 显示错误 → 用户被困在模态框里
- 模态框提示文案"验证码将发送到您的邮箱"对无邮箱用户是误导

### 触发条件

OAuth 用户无邮箱时点"设置密码"。

### 涉及文件

- `src/api/routes/grape_auth.py` 第 530-531 行（后端校验邮箱）
- `src/api/static/js/pages/account.js` 第 301-317 行（前端模态框未检查邮箱状态）
- `src/api/static/js/pages/account.js` 第 110-121 行（安全页渲染，已知 `has_password` 但未检查 `email`）

### 根因

前端 `_accountShowSetPassword()` 未检查 `_accountProfile.email`。账号安全页渲染时已有用户 profile 数据（第 105-106 行 `d.email`），可以判断是否需要先引导绑定邮箱。

## 问题 5（P2）：首次设置密码要求输入确认密码

### 是什么

设置密码模态框要求输入"新密码"+"确认新密码"两个字段。用户质疑首次设置密码时为什么还要输入确认密码。

### 影响

- 首次设置密码场景下，确认密码字段增加操作步骤，降低转化率
- 现代主流产品首次设置密码已普遍取消确认密码字段
- 密码输入框已有显示/隐藏切换功能，确认密码防错价值有限

### 触发条件

首次进入设置密码流程时必定出现。

### 涉及文件

- `src/api/static/js/pages/account.js` 第 310-311 行、第 334 行
- `docs/weekly-06/grape-account-system-requirements.md` 需求 12 第 539 行

### 根因

需求 12 明确要求确认密码字段。代码与需求一致，是 UX 设计决策问题。

## 问题 6（P1）：注销账号缺少 OAuth 重新授权认证入口

### 是什么

后端实现了无密码无邮箱用户通过 OAuth 重新授权完成注销认证的完整链路：
- `DELETE /auth/delete-account` 接收 `oauth_state` 参数（grape_auth.py 第 756-764 行）
- `GET /auth/delete-account/oauth/{provider}` 发起 OAuth 授权（第 688 行）
- 后端在无密码无邮箱时返回 `need_oauth: true` + `providers` 列表引导前端走 OAuth（第 768-779 行）

但前端注销模态框（account.js 第 1170-1197 行）只有两个选项：
- "用密码验证"（仅有密码时显示）
- "用验证码验证"（始终显示）

**没有 OAuth 重新授权的入口**。无密码无邮箱的 OAuth 用户点"用验证码验证"→ 发送验证码 → 后端返回 400 "请先绑定邮箱" → 死路。用户无法完成注销。

### 影响

纯 OAuth 用户（无密码无邮箱）无法注销账号——后端有完整实现但前端没有入口。

### 触发条件

OAuth 用户（无密码无邮箱）尝试注销账号。

### 涉及文件

- `src/api/routes/grape_auth.py` 第 688-700 行（后端 OAuth 注销接口）
- `src/api/routes/grape_auth.py` 第 768-779 行（后端返回 need_oauth 引导）
- `src/api/static/js/pages/account.js` 第 1170-1197 行（前端注销模态框，缺少 OAuth 入口）
- `src/api/static/js/pages/account.js` 第 1216-1228 行（`_accountDoDeleteAccount` 未处理 `need_oauth` 响应）

### 根因

前端注销流程实现不完整，遗漏了需求 14 修正的 OAuth 重新授权认证方式。

## 问题 7（P2）：密码输入框缺少 autocomplete 属性

### 是什么

设置密码、修改密码、注销验证的密码输入框均未设置 `autocomplete` 属性。浏览器密码管理器无法正确识别字段用途（新密码 vs 当前密码），可能自动填充错误值。

华为云 AK/SK 输入框（第 191、196 行）正确设置了 `autocomplete="new-password"`，但密码相关的输入框全部缺失。

### 影响

- 浏览器密码管理器可能将当前密码自动填入新密码字段，或反之
- 用户看到自动填充的密码不确定是哪个字段的，需要手动清除
- 影响所有需要输入密码的场景

### 触发条件

使用浏览器密码管理器（Chrome/Firefox/Safari 内置或 1Password 等扩展）时。

### 涉及文件

| 行号 | 字段 | 缺少的 autocomplete 值 |
|------|------|----------------------|
| 275 | cpCurr（当前密码） | `autocomplete="current-password"` |
| 276 | cpNew（新密码） | `autocomplete="new-password"` |
| 277 | cpConfirm（确认新密码） | `autocomplete="new-password"` |
| 310 | spPwd（设置新密码） | `autocomplete="new-password"` |
| 311 | spPwdConfirm（确认新密码） | `autocomplete="new-password"` |
| 1186 | daPwd（注销验证密码） | `autocomplete="current-password"` |

### 根因

开发时未考虑浏览器密码管理器兼容性。

## 问题 8（P2）：安全提示条样式与 Apple 设计风格不一致

### 是什么

OAuth 登录后的安全提示条（app.js 第 863-878 行）使用硬编码的黄色背景 `#fff3cd` + 黄色边框 `#ffe69c`，这是 Bootstrap 风格的 alert-warning 配色。与整体 Apple 设计风格（使用 CSS 变量 `--a`/`--t`/`--bg` 等）不一致。

### 影响

- 视觉风格割裂——黄色提示条在 Apple 风格界面中突兀
- 在 Apple 主题（Liquid Glass）下尤为明显——Apple 使用半透明毛玻璃 + 系统蓝/橙色调，不是 Bootstrap 黄
- 提示条关闭按钮样式（`bt-p`/`bt-o`）已使用 CSS 变量，但背景色是硬编码的

### 触发条件

OAuth 用户首次登录后看到提示条时。

### 涉及文件

- `src/api/static/js/app.js` 第 863-878 行（提示条 HTML + 内联样式）
- 对比：`src/api/static/css/apple-theme.css`（Apple 主题使用 CSS 变量系统）

### 根因

提示条使用内联硬编码颜色，未使用 CSS 变量系统。

## 问题 9（P2）：模态框密码输入框 label 宽度不足导致截断

### 是什么

`.srow label` 固定宽度 110px（app.css）。但"确认"这个 label（confirm_label 的值就是"确认"两个字）在 110px 宽度内显示正常，而英文模式下 "Confirm" 也 OK。

但问题在于 `.kb-input` 的宽度是固定 200px（app.css 第 631 行 `width:200px`），在 440px 宽度的模态框内（account.js 第 1240 行 `width:440px`），label 110px + input 200px + gap 10px = 320px，剩余 120px 空白。输入框偏窄，密码输入时视觉不平衡。

### 影响

- 模态框内密码输入框偏窄（200px），右侧留白多，视觉不平衡
- 在移动端（模态框 max-width:92vw）更明显——label 110px 占比过大

### 触发条件

桌面端模态框内所有包含 `.srow + .kb-input` 的表单。

### 涉及文件

- `src/api/static/css/app.css` 第 631 行（`.kb-input { width: 200px }`）
- `src/api/static/css/app.css` `.srow label { width: 110px }`
- `src/api/static/js/pages/account.js` 第 1240 行（模态框 `width:440px`）

### 根因

`.kb-input` 固定 200px 宽度是给设置页侧边栏设计的，模态框内复用了相同 class 但没有覆盖宽度。应使用 `flex:1` 或模态框内覆盖 `.kb-input { width: auto; flex: 1 }`。

## 问题 10（P3）：设置密码模态框提示文案"验证码将发送到您的邮箱"未显示具体邮箱

### 是什么

设置密码模态框第一步显示"验证码将发送到您的邮箱"（account.js 第 305 行），但没有显示具体邮箱地址。用户有多个邮箱时不确认发到哪个。修改邮箱模态框同理——"验证码将发送到新邮箱"但用户刚输入的新邮箱地址没有回显。

### 影响

- 用户不确定验证码发到哪个邮箱，需要去邮箱查找
- 如果邮箱拼写错误，用户不知道发错了哪里

### 触发条件

设置密码 / 修改邮箱流程中。

### 涉及文件

- `src/api/static/js/pages/account.js` 第 305 行（设置密码提示）
- `src/api/static/js/pages/account.js` 第 347-348 行（修改邮箱第一步，输入了邮箱但第二步提示不回显）

### 根因

提示文案是静态的，未动态插入用户邮箱地址。

## 问题 11（P3）：注销账号模态框"用验证码验证"在无邮箱时仍显示

### 是什么

注销账号模态框（account.js 第 1178-1182 行）始终显示"用验证码验证"按钮，不检查用户是否有邮箱。无邮箱用户点击后进入验证码步骤 → 点"发送验证码"→ 后端返回 400 "请先绑定邮箱" → 用户被困。

这与问题 4（设置密码前置条件）是同一类问题。

### 影响

无邮箱用户在注销流程中被引导走不通的路径。

### 触发条件

OAuth 用户无邮箱时尝试注销。

### 涉及文件

- `src/api/static/js/pages/account.js` 第 1182 行（不检查邮箱状态始终显示验证码按钮）
- `src/api/routes/grape_auth.py` 第 678-679 行（后端无邮箱返回 400）

### 根因

前端未根据用户状态动态调整注销验证方式的可用性。
