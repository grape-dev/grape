# Spec: Issue #371 — 个人引擎改为仓库级后在 Workers 设备页不可见

> Generated by Coding Agent | Branch: feat/issue-371 → weekly-08-ljt | 2026-10-19

## Objective
修复「引擎作用域从个人切换为仓库级后，Workers 设备页看不见该引擎」的可见性缺陷，并保证切换过程数据一致性。

## 根因（已定位）
`change_credential_scope`（src/api/routes/settings.py:1241）切换 scope 时存在三处叠加缺陷：

1. **org_id 未同步**：切换只改 scope/repo_key/owner_id，未同步 `runtime_credentials.org_id`。
   非个人组织视图（Workers 设备页）的 `get_agent_runtimes` / `get_runtime_devices` 按
   `rt.org_id != _filter_org_id` 严格过滤，repo scope 凭据/引擎若 org_id 不匹配被滤除。
2. **owner_id 被无条件清空（line 1288）**：repo scope 切换时 line 1268 写入 `owner_id=repo_key`，
   随后 line 1288 又执行 `UPDATE ... SET owner_id=''` 把它抹掉。导致 repo scope 凭据 owner_id 恒空，
   `_visible_credential` 的 `from_repo_key(cowner_id)` 回退到 crepo_key 才能判定，多了一层脏数据。
3. **非个人组织严格隔离分支无 repo 豁免**：#338 已为「个人组织视图」补了 repo scope 豁免，
   但「非个人组织视图」（`_filter_org_id > 0` 分支）仍是纯 org_id 严格过滤，repo scope 引擎若
   org_id != 当前组织 org_id 直接 continue，无 #338 同口径豁免。

## Scope (In)
1. `change_credential_scope`：user→repo / repo→user 转换时同步 credential.org_id 与归属对齐；
   修复 line 1288 无条件清 owner_id 的 bug（repo scope 保留 repo_key 作为 owner_id）。
2. `get_agent_runtimes` / `get_runtime_devices`：非个人组织严格隔离分支为 repo scope 增加与 #338
   同口径豁免（repo scope 且 repo_key/owner_id 指向用户可访问仓库时不被 org_id 过滤），
   复用 `_visible_credential` 防越权。
3. 历史脏数据 org_id 存量修正：切换入口同步修正存量（每次切换把 org_id 对齐到当前归属）。
4. 新增 `tests/test_issue_371_scope_change_visibility.py`。

## Acceptance Criteria
- 切换为仓库级后刷新 Workers 设备页引擎可见；场景引擎可选
- scope/owner_id/org_id/repo_key 落库一致，无孤儿/重复引擎行
- 回归 #338（个人组织视图个人设备可见）与 #277（仓库隔离不越权）不回退
- 所有现有测试通过 + 新增测试覆盖

## Out of Scope
