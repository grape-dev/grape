# Spec: Issue #4341 — 字母数字单号按「首个数字串」归组导致 events 串号 / pipeline 恒空

> Generated by Coding Agent | 2026-11-25 | 基线 `arch-weekly-11-ch`（头 `baa09e5c7`）
> 上游 Spec 见 Issue #4341 评论（issue 阶段，评级 ready）；本文件是编码阶段的落地切片。

## Objective

- 要构建什么：issue 事件/流水线的归组键由「首个数字串」改为「**平台前缀 + 完整编号**」，
  使同仓 `#IKXR3A` / `#IKXR3B` / `#IKXR3C` 各自独桶，且不再与纯数字 `#3`（含跨平台同号）撞桶。
- 为什么：`_num_from_issue_id()` 用 `re.search(r"(\d+)")` 抠首个数字串（`#IKXR3B` → `"3"`），
  三个 Gitee 单号的事件被合并进键 `"3"`；`get_issue_pipeline` 用完整编号查该 map 恒 miss
  → `segments=[]`、`status=unknown`；`get_issue_events` 因同键返回到其它 issue 的事件。
  复现：`example/hello-skill`（IKXR3A/B/C）。
- 用户：Agent（VOD/issue/coding/qa/sre 读事件与流水线）、grape CLI `issues detail/pipeline/events`、
  插件面板（节点链全灰 / 实时卡片退化）。
- 成功标准：Issue 验收条款全部通过；纯数字单号（gitcode/github/gitlab）行为零变化。

## Scope

### In Scope

1. `src/domains/runtime/routes/issues.py`
   - `_num_from_issue_id()`：`#` 后整串即编号（`#IKXR3B` → `IKXR3B`），`#pr_*` 伪 ID 仍返回空，
     `5` / `#5` 兼容；
   - `_group_events_by_issue()`：归组键 = `<provider>:<完整编号>`，逐 `repo_key` 归组，
     不跨 `repo_keys` 合并同号；行内补取 `repo_key` 列；
   - 新增单一键构造助手 `_issue_group_key()`、候选键集合 `_issue_group_keys()`、
     取值助手 `_issue_group_events()`（同 ident 跨平台桶按 seq 合并，不同 ident 不混合），
     `get_issue_detail` / `get_issue_events` / `get_issue_pipeline` / `_assemble_issue` /
     `_issue_title_map` / `_resolve_issue_presence` / 列表页富化全部改用它，消除口径分裂；
   - `_issue_stage_map()` 的 `issue_state` 兜底与 `issue` 单表键对齐（完整 ident）；
   - `get_issue_events` 的编号归一改走 `_normalize_issue_number()`（与另两入口同口径）。
2. `src/domains/runtime/routes/tasks.py`：`tasks/current` 关联需求富化同属该家族缺陷
   （`re.sub(r"[^0-9]","")` 抠数字 + 按裸编号取 group），随本次键改造一并收敛（否则键改造后静默空）。
3. `src/api/event_archive.py`：`build_issue_context()` 的 group 取值改用同一助手。
4. 测试：新增 `tests/runtime/test_issue_4341_ident_grouping.py`（单号解析、分组键唯一、
   跨平台同号不合并、`_issue_stage_map` 兜底对齐、`/events` 与 `/pipeline` HTTP 级串号回归）。

### Out of Scope

- `_query_pr_subscription_events()` 的 PR 号解析（`isdigit()` 前置已存在，仅纳入回归）；
- 其它 `re.search(r"(\d+)")` 家族（`event_archive._extract_num`、`knowledge`、`release_guard`、
  `feedback`、`routes/events.py` 的档案段定位）——各自独立功能面，不属本单归组链路；
- 客户端（插件 0.5.3）空态降级改造；
- `issue` / `issue_state` 表主键口径与 #4328/PR #2149 的 `int()` 清理（协同回归，不重复实现）。

## Acceptance（对齐 Issue 验收条款）

- [ ] `#IKXR3A` / `#IKXR3B` / `#IKXR3C` 的 `/events` 与 `/pipeline` 各只返回自身事件（IKXR3B 为空）；
- [ ] `/issues/{owner}/{repo}/3/pipeline` 不再返回 Gitee 事件（纯数字 `#3` 只返回自身事件）；
- [ ] `issues pipeline --number IKXR3A` 的 `segments` 非空且节点状态与事件一致；
- [ ] 字母数字单号不再触发 `int()` 转换异常（无 `except` 吞错）；
- [ ] 单测：同仓混合「纯数字 + 字母数字」单号时分组键唯一；
      `_num_from_issue_id`：`#IKXR3B→IKXR3B`、`#5→5`、`5→5`、`#pr_1_x→""`。

## Risks / 兼容

- 归组键形状变更属内部约定：`_group_events_by_issue()` 的返回值只在进程内消费
  （`issues.py` 自身 + `tasks.py` + `event_archive.py`），不外泄为 API 契约；调用点本次全部随迁。
- 裸 `repo_key`（历史写入行）按 `parse_repo_key()` 默认 provider（`gitcode`）归组，
  候选集含裸键本身，存量行仍可被同一逻辑仓库查到，不需要数据迁移。
- 跨 `repo_keys` 不再合并同号是**有意**收紧：同号但不同 provider 的事件此前是错的，不应兼容。
