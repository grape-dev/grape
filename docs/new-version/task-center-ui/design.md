# 任务中心 UI 重新设计

> 目标：解决当前任务中心页面「字体、排版不协调」的问题，输出 **2 版专业设计方案**（含 ASCII 原型图 + HTML 高保真），页面既不过空也不过满，与现有 Lobby / 项目模板的视觉语言保持一致。
> 关联文档：`user-workflow-overview.md`、`templates.js` 场景色卡片、`app.css` lobby 设计 token

---

## 〇、现状分析

### 0.1 当前页面（tasks.js）

```
┌────────────────────────────────────────────────┐
│ 任务中心   [● 待处理] [✓ 已完成]        📦 repo │
├────────────────────────────────────────────────┤
│ ┌────────────────────────────────────────────┐ │
│ │ 📋 Issue #12 · owner/repo      ● 待处理    │ │
│ │ 标题文本                                    │ │
│ │ 任务描述文本                                │ │
│ │ ⏱ 2026-08-05 12:00                         │ │

│ └────────────────────────────────────────────┘ │
│ (... 列表卡片 ...)                              │
└────────────────────────────────────────────────┘
```

### 0.2 问题

| 问题 | 说明 |
|------|------|
| **排版平淡** | 单一卡片列表，无层次、无留白节奏，视觉重量失衡 |
| **字体不协调** | 内联样式字号混乱（16px/14px/13px/12px/11px 混用），标题/正文层级不清晰 |
| **无数据总览** | 顶部无统计，页面"太空"或缺上下文 |
| **无状态可视化** | 待处理/已完成只有文字 tag，无图标/进度/优先级等视觉信号 |
| **响应式不足** | 依赖内联布局，窄屏表现不佳 |

### 0.3 复用设计 token

沿用现有 `app.css` 的视觉语言，保证一致性：

- **配色**：`--a`(#3168e0 主蓝)、`--g`(#1ca44c 绿)、`--pu`(#7b3cf2 紫)、`--r`(#dc2828 红)、`--or`(#ea5a0c 橙)
- **卡片**：`border:1px solid var(--b)`、`border-radius:16px`、`box-shadow`、hover 上浮 + 顶部渐变线
- **图标**：彩色渐变底 `linear-gradient(135deg,#eaf0ff,#ede8fd)` + 圆角容器
- **胶囊**：`border-radius:20px` + 淡色底 + 状态圆点
- **头部**：`lobby-eyebrow`（小字眉标）+ `lobby-title`（渐变大标题）+ `lobby-sub`（副标题）

## 一、设计原则

1. **信息层级清晰**：总览统计 → 筛选控制 → 任务列表，三区块节奏分明。
2. **状态即视觉**：待处理（蓝/橙动势）、已完成（绿/灰静置），用颜色 + 图标 + 圆点三重信号。
3. **留白与密度平衡**：卡片间距 16px，内边距 20px，正文 13px / 行高 1.6——既不空洞也不拥挤。
4. **数据可见**：顶部统计（总数/待处理/已完成）+ 按仓库分组的次级信息，让页面"有内容"。
5. **与全局一致**：复用 lobby/tmpl 的渐变、圆角、hover 交互，用户无缝衔接。

## 二、方案 A：工作台风（Workspace Dashboard）

> 定位：任务中心作为"工作台"，顶部统计概览 + 状态分组，突出待处理优先级。适合待办驱动的用户。

### 2.1 布局结构

```
┌───────────────────────────────────────────────────────────┐
│  ── TASK CENTER ──                                         │
│  任务中心                                                    │
│  管理分配给你的 Issue 任务，跟踪处理进度与结果。               │
│  ┌────────┐ ┌────────┐ ┌────────┐                          │
│  │ 总任务  │ │ 待处理  │ │ 已完成  │    📦 owner/repo [筛选▾] │
│  │  12    │ │   5    │ │   7    │                          │
│  └────────┘ └────────┘ └────────┘                          │
│  ──────────────────────────────────────────────            │
│  ● 待处理 (5)               [按时间排序▾]  [清除]           │
│  ┌────────────────────────────────────────────────────┐   │
│  │ ◧   Issue #12 · 商品详情页加载优化        ● 待处理   │   │
│  │     商品详情接口超时导致白屏，需要优化……              │   │
│  │     ⏱ 2小时前 · owner/repo                           │   │
│  │     [去对话] [查看 Issue ↗]                           │   │
│  └────────────────────────────────────────────────────┘   │
│  ✓ 已完成 (7)                                             │
│  ┌────────────────────────────────────────────────────┐   │
│  │ ✓   Issue #9 · 首页推荐位调整        ✓ 已完成·关闭  │   │
│  │     ⏱ 昨天 · owner/repo                             │   │
│  │     [查看会话] [查看 Issue ↗]                        │   │
│  └────────────────────────────────────────────────────┘   │
└───────────────────────────────────────────────────────────┘
```

### 2.2 设计要点

| 元素 | 设计 |
|------|------|
| **头部** | `lobby-eyebrow`（TASK CENTER 眉标）+ `lobby-title` 渐变标题 + 副标题，居中 |
| **统计条** | 3 个 `lobby-stat` 卡片（总任务/待处理/已完成），待处理数字用 `--or` 强调 |
| **仓库筛选** | 右上角胶囊下拉（当前仓库 + 全部），复用 `.lobby-card-status` 胶囊样式 |
| **分组** | 待处理组 + 已完成组，各带分组标题（彩色圆点 + 计数） |
| **任务卡片** | 左图标（彩色渐变底，待处理=橙/蓝，已完成=绿）+ 标题 + 描述（2行截断）+ 元信息行 + 操作按钮 |
| **空态** | 复用 `.lobby-empty`，图标 + 文案 + 引导 |

### 2.3 字体体系

- 标题：`18px/600`（卡片标题）、`15px/600`（分组标题）
- 正文：`13px/400`，`line-height:1.6`，`color:var(--t2)`
- 元信息：`11px`，`color:var(--t3)`
- 统计数字：`24px/700`

## 三、方案 B：列表工作流风（Flow List）

> 定位：任务中心作为"流程看板"，单列流水 + 右侧信息栏，突出上下文与操作效率。适合需要专注逐个处理的用户。

### 3.1 布局结构

```
┌───────────────────────────────────────────────────────────┐
│  TASK CENTER         [全部|待处理|已完成]  [🔍 搜索] [筛选▾] │
│  任务中心 · owner/repo                                      │
├──────────────────────────────────┬────────────────────────┤
│  ● 待处理                        │  任务详情               │
│  ┌────────────────────────────┐  │  ┌──────────────────┐  │
│  │ ◧ #12 商品详情页加载优化    │  │  │ Issue #12        │  │
│  │    2小时前 · 待处理         │  │  │ 商品详情页加载优化 │  │
│  └────────────────────────────┘  │  │ ● 待处理          │  │
│  ┌────────────────────────────┐  │  │ ──────────────── │  │
│  │ ✓ #9 首页推荐位调整        │  │  │ 任务描述……        │  │
│  │    昨天 · 已完成·关闭       │  │  │                  │  │
│  └────────────────────────────┘  │  │ ⏱ 创建于 08-05    │  │
│  ┌────────────────────────────┐  │  │ [去对话] [Issue↗]  │  │
│  │ ✓ #7 订单状态同步          │  │  └──────────────────┘  │
│  │    08-04 · 已完成·转派      │  │                       │
│  └────────────────────────────┘  │   📋 关联会话           │
│  (点击行 → 右侧详情)             │  ┌──────────────────┐  │
│                                  │  │ 对话预览……        │  │
│                                  │  │ [打开对话]         │  │
│                                  │  └──────────────────┘  │
└──────────────────────────────────┴────────────────────────┘
```

### 3.2 设计要点

| 元素 | 设计 |
|------|------|
| **顶部** | 紧凑头栏：眉标 + 标题 + 状态胶囊 tab（全部/待处理/已完成）+ 搜索 + 筛选 |
| **主区** | 左侧任务列表（紧凑行，hover 高亮 + 左侧状态色条），右侧固定 320px 详情面板 |
| **行样式** | 图标 + 标题 + 相对时间 + 状态胶囊；已完成行降饱和（透明度/灰绿） |
| **详情面板** | 选中任务展示：Issue 号、标题、状态、描述、创建时间、操作按钮、关联会话预览 |
| **主次分明** | 左列表 60%、右详情 40%，页面"不空不满" |

### 3.3 字体体系

- 头栏标题：`20px/700`
- 列表行标题：`14px/600`
- 详情标题：`18px/600`
- 正文：`13px/400`，`line-height:1.7`
- 元信息：`11px`，`color:var(--t3)`

## 四、对比与推荐

| 维度 | 方案 A：工作台风 | 方案 B：列表工作流风 |
|------|----------------|---------------------|
| **视觉重点** | 统计总览 + 状态分组 | 高效列表 + 详情联动 |
| **信息密度** | 中（一屏多看几条） | 中高（列表紧凑，详情聚焦） |
| **空态友好** | 好（有统计骨架） | 中（列表空但详情可用） |
| **适合场景** | 快速浏览待办优先级 | 逐个深入处理任务 |
| **实现复杂度** | 低（单列分组卡片） | 中（双栏 + 选中联动） |
| **视觉专业度** | ★★★★ | ★★★★★ |

**推荐**：若追求专业与高效，选 **方案 B**；若偏重一眼概览，选 **方案 A**。两者都大幅优于现状。
