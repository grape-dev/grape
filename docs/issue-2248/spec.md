# Spec: Issue #2248 — A2A 固定 idempotency_key 导致修复轮无法重新派发 QA

> Generated by Coding Agent | 2026-11-12 | 基线分支：weekly-mys（本流水线注入；前序 Spec 的 arch-weekly-11 为前序流水线基线）

## Objective
修复轮（第二轮及以后）重新派发 QA 复审时，A2A 交办必须能落一条新事件，不得因固定
`idempotency_key` 永久命中首轮已 completed 的旧事件而被吞。

## Scope
### In Scope
- `POST /api/a2a`：`force` 解析前移到幂等键命中判定之前；`force=true` 且命中终态旧事件时
  跳过命中短路，按派生新轮次键落库；命中响应补 `existing_status` / `replayable`。
- 幂等键生成规则纳入轮次或 PR head sha（runbook 建议 `issue-<N>-a2a-qa-r<轮次>-<sha7>`）。
- 契约文档（`help/api/12-a2a.md`、`docs/openapi/12-a2a.md`、contracts schema）、
  `A2AHandoffBody` description（随 OpenAPI 进入 `grape a2a handoff --help`）同步。
- 单测覆盖「key 命中 + `force=true` 可重派」与「key 命中 + 无 `force` 返回原事件」。

### Out of Scope
- #2241 重复派发治理；#2242 幂等响应契约整体重构；#2210 判定表补充。

## Technical Approach
1. `src/api/routes/webhook.py`：在鉴权后的幂等命中查询前解析 `_force` / `_queue` /
   `_a2a_ctx_key`；命中且 `force=true` 且旧事件为终态（completed/failed/cancelled/timeout）
   时，用 `-fr-<seq>[-n]` 派生新键继续落库；其它命中仍返回原事件（含状态字段）。
2. `src/api/event_store.py`：保持 `(repo_key, idempotency_key)` 唯一性，不改查询/落库语义。
3. 契约与 help 文档：`idempotency_key` / `force` 描述、命中响应示例、判定表同步
   `idempotent` / `existing_status` / `replayable` 分支。
4. 测试：`tests/test_issue_2248_a2a_idempotency_force_replay.py`。

## Acceptance Criteria
- [ ] 首轮 key 事件 completed 后，第二轮 `force=true` 同键交办返回新 seq（非旧 seq）。
- [ ] 第二轮使用 `issue-N-a2a-qa-r2-<sha7>` 新键交办，返回新 seq 且不判 duplicate。
- [ ] 同一轮次同一键、无 force 的重复请求仍返回原事件（`idempotent:true`），不产生第二条。
- [ ] 命中响应带 `existing_status` / `replayable`，判定表可据此分支。
- [ ] 单测覆盖「key 命中 + force=true」与「key 命中 + 无 force」。
- [ ] 现有测试通过。

## Risks & Mitigations
| Risk | Impact | Mitigation |
|------|--------|------------|
| force 放宽导致重复派发 | Med | 仅终态事件允许重派；活跃事件仍返回原事件 |
| 派生键与唯一索引冲突 | Low | 派生时查重并递增序号；长度截断至 128 |
| 文档与实现漂移 | Low | 契约/help/runbook 同一 PR 同步 |
