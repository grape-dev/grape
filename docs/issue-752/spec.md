# Spec: Issue #752 — PR 合入/自动复测流程冲突残留防护门禁

> Developability: ready | 2026-11-03 | 目标分支: weekly-08-mys（跨流水线移交后基线，原 Spec 记录 weekly-09 作废）

## Objective
- 构建：合入流程冲突标记扫描门禁 + 服务端自动提交/推送与任务工位清理对非产物功能文件的保真校验，防止未解决 merge 冲突文本被整体写入分支、覆盖已合入的功能修改。
- 为什么：PR #352（fix #778）合入 dev-dzr 后 runbook 由 364→1037 行、含 11 处 `>>>>>>>`/`=======` 冲突标记与 3 个重复 Step 4b 块，属合入流程数据损坏（P1）。
- 成功标准：AC1/AC2/AC3 全部可测试通过。

## 根因定位（本仓服务端职责范围）
1. **合入口**：`src/api/git_repo_api.py::merge_pull` 是平台侧合入网关，直接透传上游 merge，**无任何冲突标记扫描**——含冲突残留的 PR 分支可被无条件合入基线（AC1/AC3 缺失点）。
2. **服务端自动提交/推送口**：`src/runtime/agent.py::_submit_linked_repo_prs` 与 `src/api/event_pipeline.py` direct 版 linked PR 流程对 worktree 执行 `git add -A → commit → push`，**盲目整树提交**——worktree 中任何未解决的 merge 冲突文本会被原样写入分支（复测/清理环节残留进入分支的具体通道）。
3. **任务工位清理口**：`_cleanup_task_workdir` / `_cleanup_direct_workdir` 只删物化轻文件 + 卸载 worktree，**对清理前后非产物功能文件无指纹比对**（AC2 缺失点）。

## Scope
### In
- M1：`merge_pull` 新增冲突标记扫描门禁（合入前对 PR 变更文件扫描，硬命中 `<<<<<<< `/`>>>>>>> ` → 阻断 409 + 记合入日志；仅 `=======` 软命中 → 告警放行；合入后再扫描一次，命中 → 告警 + 合入日志）；
- M2：自动提交/推送前对暂存文件做冲突标记扫描（硬命中阻断 push，防止残留写入分支）；任务开始时保存功能文件指纹基线，任务结束/清理时校验指纹一致（不一致 → 告警日志，不阻断清理）；
- 合入日志落库 `grape_t_merge_gate_log`（决策/命中明细/时间，幂等建表迁移）；
- M3：新增单测覆盖门禁与保真两轴（命中/放行）。

### Out of Scope
- 已损坏历史分支文件的人工修复（另行处理）；
- GitCode 平台侧 merge 能力本身的改造；
- agent 技能仓（grape-skills）侧的复测 runbook 行为（属技能仓职责）。

## 关键设计决策
| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 门禁扫描时机 | 仅合入后 / 合入前+后 | 前+后双扫 | 合入前扫描才能真正"阻断"（防残留进入分支，AC1）；合入后扫描覆盖自动复测等旁路引入的残留（Spec 原决策），命中走告警+日志（AC3） |
| 硬/软命中分级 | 全部阻断 | `<<<<<<< `/`>>>>>>> ` 硬命中阻断；孤立 `=======` 软命中仅告警 | Markdown 标题下划线 `=======` 是合法文档语法，全量阻断会误杀（Spec 风险缓解：误报走告警不阻断） |
| 门禁失败语义 | 失败即拒合 | fail-open（扫描异常记 warning 放行） | 门禁自身故障不应阻断正常合入流水线（与台账 record_outbound 同语义） |
| 指纹基线存放 | worktree 内 / worktree 外 | 外（`<wt_dir>.fidelity.json` 兄弟文件） | 放 worktree 内会被 agent `add -A` 误提交 |
| 保真校验失败 | 阻断清理 | 告警日志 | 清理是收尾路径，阻断会造成 worktree 残留；告警供人工裁决（Spec：阻断有再次损坏风险，需人工裁决） |

## Acceptance Criteria
- [ ] AC1：门禁硬命中时 merge 被阻断（409），合入后分支功能文件无 `<<<<<<< `/`>>>>>>> ` 冲突标记残留
- [ ] AC2：自动提交/推送口对暂存文件硬命中阻断 push；任务清理前后功能文件指纹比对，不一致产生告警记录
- [ ] AC3：门禁每次决策（blocked/warned/passed/alarmed）均记录到合入日志表 `grape_t_merge_gate_log`
- [ ] 所有现有测试通过；新增测试覆盖门禁与保真校验两轴（命中/放行）
