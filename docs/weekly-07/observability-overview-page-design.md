# 可观测性 · 「总览」页图表设计方案

> 状态：**待评审**（副设计文档）
> 主文档：`docs/weekly-07/observability-redesign-design.md`（§5.2 分区 ①）
> 范围：仅「总览」分区的页面布局、图表清单与交互；不含设备与引擎 / 任务与日志分区
> 前提：侧栏已定稿（可观测性 = 一级分类，3 子项）

---

## 1. 设计目标

总览页只回答三个问题，**答不上来的图就不放**：

1. **现在健康吗？** —— 一眼看到好坏（KPI + 告警横幅）
2. **哪里不对？** —— 趋势图暴露拐点，健康分图指出是哪个引擎
3. **下一步点哪？** —— 每张图都能点进对应分区，带好过滤条件

**反面清单（明确不做）**：
- ❌ 不做可自由拖拽的自定义大盘（P2 再议）—— 首创版本固定布局，保证"打开就懂"
- ❌ 不做无下钻的死图 —— 每张图必须能点进去
- ❌ 首屏图表 > 6 个 —— 超过就是报表不是总览
- ❌ 不出现数据库/平台基础设施指标（连接池、库表、主机拓扑）—— 见主文档 §5.3

## 3. 图表库选型

| 方案 | 体积 | 优劣 | 结论 |
|---|---|---|---|
| **ECharts 5** | ~1MB（min） | 图表类型齐（双轴/堆叠/面积/热力/仪表）、tooltip·legend·dataZoom 开箱即用、单文件 UMD 免构建、Apache-2.0 与 grape 开源许可兼容、中文文档 | ✅ **采用** |
| uPlot | ~40KB | 时序极快，但柱状/条形要自己拼，样式定制成本高 | 备选 |
| Chart.js | ~200KB | 轻，但双轴+堆叠+dataZoom 组合不如 ECharts | 备选 |
| 自研 SVG | 0 | 无依赖，符合现有"纯 HTML+JS"风格；但 6 张图 + tooltip + 图例 + 缩放，工作量远超收益 | ❌ |

**落地方式**：`src/api/static/vendor/echarts.min.js`（本地 vendored，**不走 CDN** —— 内网/离线部署必须自持），`index.html` 加一个 `<script>`。许可文件一并放 `vendor/LICENSE-echarts`（开源合规）。

**统一主题**：封装 `obsChart(el, option)` 小工具，统一取当前 CSS 变量（`--bg/--t1/--t2/--t3`）生成配色，跟随深浅色主题；统一色板：

| 语义 | 色值 | 用在哪 |
|---|---|---|
| 成功 | `#22a06b` 绿 | 任务成功、健康分 ≥90 |
| 失败 | `#d64545` 红 | 任务失败、ERROR |
| 警告 | `#e0a02a` 黄 | 取消/卡住、WARNING、健康分 70-89 |
| 中性 | `#4a7fd1` 蓝 | 排队中、执行中、队列深度 |
| 弱化 | `#8b8b8b` 灰 | 其他/无数据 |

## 4. 图表详设

### ① 任务量与结果（主图，8 列）

| 项 | 内容 |
|---|---|
| 图型 | **堆叠柱状图 + 折线（双 Y 轴）** |
| X 轴 | 时间桶（自适应：1h→1min / 6h→5min / 24h→30min / 7d→3h） |
| 左 Y 轴 | 任务数（整数） |
| 右 Y 轴 | 成功率 %（0-100，固定刻度，避免视觉放大波动） |
| 系列 | `成功`(堆叠) / `失败`(堆叠) / `取消`(堆叠) / `成功率`(折线，右轴，不堆叠) |
| 数据源 | `agent_tasks` 按 **`created_at`** 分桶（见口径说明）；长期用 `obs_metric_rollup` |
| **口径** | **按创建时间分桶**（不是完成时间）——否则耗时长的任务会漂到后面的桶，趋势失真。成功率 = 桶内 `completed / (completed + failed + cancelled)` |
| 交互 | hover 出 tooltip：`14:30 · 共 23 个 · 成功率 94.2% · 失败 1 取消 1`；**点击某个桶** → 跳「任务与日志」并按该时间窗 + 结果过滤 |
| 空态 | 该时段无任务："所选时段没有任务" |
| 交付 | **P0** |

### ② 引擎健康分（4 列）

| 项 | 内容 |
|---|---|
| 图型 | **横向条形图**（Y = 引擎名，X = 0-100） |
| 数据 | `runtime_health_scores`（现有表，已有 health_score / failure_rate / consecutive_failures）+ `agent_runtimes.name` |
| 排序 | **最差优先**，只显示 Top8 —— 总览的目的是找问题，健康的不必占版面 |
| 配色 | ≥90 绿 / 70-89 黄 / <70 红；条右侧标数值 |
| 交互 | hover 显示 `失败率 8.3% · 连续失败 2 次`；**点击条** → 跳「设备与引擎」并定位该引擎 |
| 边界 | 只列**调用者可见**的引擎（他人设备不出现） |
| 空态 | 无引擎："还没有引擎接入" + 引导按钮 |
| 交付 | **P0** |

### ③ 任务耗时构成（6 列）

| 项 | 内容 |
|---|---|
| 图型 | **堆叠面积图** |
| X 轴 | 时间桶（同上） |
| Y 轴 | 秒 |
| 系列 | `排队等待`（均值）+ `实际执行`（均值），堆叠后 = 端到端平均耗时 |
| 数据源 | `agent_tasks`：排队 = `started_at - created_at`；执行 = `completed_at - started_at` |
| **为什么用均值不是总和** | 总和会被任务数量放大，看不出单任务体验；均值才能回答"是卡在排队了，还是跑得慢" |
| 交互 | hover：`14:30 · 排队 12s + 执行 3m10s`；点击 → 「任务与日志」带时间窗 |
| 交付 | **P0** |

### ④ 队列与在跑（6 列）

| 项 | 内容 |
|---|---|
| 图型 | **面积图**（三条独立面积，非堆叠，因为三者是并列状态） |
| X 轴 | 时间桶；Y 轴：任务数 |
| 系列 | `排队中`(蓝) / `执行中`(绿) / **`卡住`**(黄，单独强调) |
| 数据源 | `obs_metric_rollup` 的每分钟瞬时值（`grape_task_queued/running/stuck` 的落库版本） |
| 交互 | hover 显示三个数；**点击"卡住"区域** → 「任务与日志」并自动套用"运行 > 15 分钟"过滤 |
| 交付 | **P0** |

### ⑤ 日志与错误趋势（6 列）

| 项 | 内容 |
|---|---|
| 图型 | **堆叠柱状图** |
| X 轴 | 时间桶；Y 轴：条数 |
| 系列 | `ERROR`(红) / `WARNING`(黄) |
| 数据源 | `obs_log` 按 level 分桶（新增表，见主文档 §6.3） |
| 交互 | 点击柱 → 「任务与日志」下部的日志检索，带时间窗 + 级别 |
| 空态 | 无日志 → "该时段没有错误日志"（**这是好消息，用绿色文案**，不要做成"无数据"的灰色空态） |
| 交付 | **P1**（依赖 `obs_log` 表落地） |

### ⑥ 我的设备资源（6 列）

| 项 | 内容 |
|---|---|
| 图型 | **多线折线图** |
| X 轴 | 时间桶；Y 轴：百分比 0-100 |
| 系列 | `CPU` / `内存` / `磁盘` |
| 数据源 | `obs_metric_rollup` 的 `device=<name>` 维度（由现有 15s 主机采集落库而来） |
| 多设备处理 | 默认展示**可见设备的均值**；图例可展开单个设备（设备数 > 5 时只列 Top5 + "其他"） |
| 交互 | 点击 → 「设备与引擎」并选中该设备 |
| 边界 | 只显示调用者可见设备的资源，不暴露主机名/IP |
| 交付 | **P1** |

### ⑦ 最近异常任务（表格，整行）

| 项 | 内容 |
|---|---|
| 类型 | 表格（不是图表），最多 5 行 |
| 列 | 任务（可读标签：`#1234 · coding · repo-x`，**不显示 raw task_id**）/ 结果 / 耗时 / 结束时间 / 失败原因（截断 60 字，hover 看全） |
| 数据源 | `agent_tasks` where status in (failed, cancelled) order by completed_at desc |
| 交互 | 行点击 → 展开「任务与日志」的该任务时间线 |
| 脱敏 | 失败原因统一过 redaction（token/密码不落界面） |
| 交付 | **P1** |

### KPI 卡片（4 个，非图表但有迷你趋势线）

| KPI | 主值 | 迷你图 | 对比基准 |
|---|---|---|---|
| 队列深度 | 当前排队数 | 所选时段的 sparkline | 较上一同时长（+4 / -2） |
| 成功率 | 所选时段成功率 | sparkline | 同上，**下降标红** |
| P95 耗时 | 所选时段 P95 | sparkline | 同上，**上升标红** |
| 引擎在线 | 在线/总数 | sparkline | 掉线则标红并给出台数 |

> sparkline 用 ECharts 的迷你配置（无轴无图例，仅折线 + 渐变填充，高度 28px）实现。

## 5. 全局交互规范

| 项 | 规范 |
|---|---|
| **时间范围** | 页面级控件 `1h / 6h / 24h / 7d`，默认 **24h**；变化后所有图表 + KPI 基准一起刷新；写进 URL（`?range=24h`）可分享 |
| **仓库筛选** | 沿用主服务现有"选中仓库"口径；`?repo=` 入 URL；切仓库后整页刷新 |
| **自动刷新** | 默认 **30s**，但只刷新"活数据"（KPI、④ 队列与在跑、⚠ 告警横幅）；趋势图（①②③⑤⑥）**不自动重绘**（避免图表闪烁跳动），改为每 5 分钟或手动刷新 |
| **手动刷新** | 右上角按钮，刷新全部并显示最后更新时间（"12:04:31 更新"） |
| **图表点击下钻** | 每张图的点击都跳到对应分区并**带上过滤条件**（时间窗/仓库/引擎/级别），且过滤条件在 URL 上可见可改 |
| **tooltip** | 统一格式：第一行时间，后续 `标签 · 值`；数值带单位（个 / % / 秒，秒自动折算 m/s） |
| **空态** | 分两种语义：**无数据**（灰，中性文案）/ **无异常**（绿，正向文案，如"该时段没有错误日志"） |
| **加载态** | 骨架屏（灰色占位块），不要"加载中…"文字；单图失败时只让该图显示"加载失败 · 重试"，不整页报错 |
| **图例** | 可点击切换显隐；默认全显；用户切换后记住（localStorage，按图 id） |
| **点数上限** | 任何系列的桶数 ≤ 60（超出自动加粗桶宽），避免柱条细如发丝 |
| **百分位口径** | P50/P95/P99 在服务端用桶内聚合算，前端不重算 |

## 6. 后端接口

**单接口聚合**，避免首屏 6~8 个并发请求：

```
GET /api/obs/overview?repo=<repo_key>&range=24h&tz=+08:00
```

```jsonc
{
  "range": "24h",
  "bucket_seconds": 1800,
  "generated_at": "2026-10-17T12:04:31+08:00",
  "alerts": { "firing": 2, "latest": { "name": "任务失败率超过 50%", "since": "..." } },
  "kpis": [
    { "key": "queue_depth", "value": 12, "delta": 4,  "spark": [3,5,8,7,12] },
    { "key": "success_rate", "value": 94.2, "delta": -1.8, "spark": [...] },
    { "key": "p95_duration_s", "value": 192, "delta": 22, "spark": [...] },
    { "key": "engines_online", "value": 6, "total": 7, "spark": [...] }
  ],
  "charts": {
    "task_outcome":   { "buckets": [...], "completed": [...], "failed": [...], "cancelled": [...], "rate": [...] },
    "engine_health":  [ { "engine": "eng-a", "score": 92, "failure_rate": 0.02, "consecutive_failures": 0 } ],
    "duration_split": { "buckets": [...], "queue_wait_avg": [...], "run_avg": [...] },
    "queue_running":  { "buckets": [...], "queued": [...], "running": [...], "stuck": [...] },
    "error_trend":    { "buckets": [...], "error": [...], "warn": [...] },
    "device_res":     { "buckets": [...], "cpu": [...], "mem": [...], "disk": [...] }
  },
  "anomalies": [
    { "task": { "id_suffix": "a1b2", "label": "#1234 · coding · repo-x" }, "status": "failed",
      "duration_s": 512, "finished_at": "...", "reason": "构建失败：找不到依赖 xxx" }
  ]
}
```

**实现要点**：
- 所有查询**先套可见范围**（调用者可见仓库 + 可见设备），越权过滤在 SQL 层完成
- 分桶聚合用 `FLOOR(UNIX_TIMESTAMP(created_at)/bucket)`，一次 `GROUP BY` 拿全，禁止按点循环查询
- 结果缓存 **30s**（键 = `user_scope + repo + range`），命中率会很高（多人同看一个仓库）
- `range=7d` 时优先读 `obs_metric_rollup`（已聚合），不再扫明细表
- **不下发任何** DB/平台指标；`anomalies[].reason` 过 redaction

## 8. 验收标准

1. 1440px 首屏**无需滚动**即可看到全部 4 个 KPI + ① ② 图；总图表数 ≤ 6
2. 切换时间范围 / 仓库后，全部图表与 KPI 基准**一致更新**，且状态可分享（URL 直达同视图）
3. 每张图表**点击都能下钻**到对应分区，且过滤条件透传到目标页（可见、可清）
4. 无数据 / 无异常两种空态语义正确区分（后者为正向绿色文案）
5. 单图加载失败不影响其他图；页面无 JS 报错（`node -c` + 浏览器 console 干净）
6. 首屏接口 **1 个**（`/api/obs/overview`），响应 < 500ms（24h 范围、缓存未命中）
7. 页面与接口响应中**不出现** DB/平台信息、raw task_id、token；越权仓库的数据不出现
8. 深浅色主题下图表可读（轴、网格线、tooltip 对比度达标）

## 9. 实施状态（slice 2 已完成）

实现日期：2026-10-17。**已完成**：KPI 行 + ①②③ 三张图（其余图见"未做"）。

### 后端 `GET /api/obs/overview`
- 服务层 `src/observability/overview.py`，路由 `src/api/routes/observability.py`（`require_org_member`）
- 单请求返回全部卡片数据（验收标准 6）；`range` 支持 `1h/6h/24h/7d`，非法值回落 `24h`
- **可见范围后端强制**：`repo` 参数先解析可见集合（`user_repos` 缓存 + 组织隔离，与 `/repos/member` 同源），
  越权抛 `RepoNotVisible` → 路由转 **404**；可见集合为空**返回空聚合而不是全量**
- 设备/引擎数复用 `runtime_credentials` 的 scope/owner/repo 可见性口径（与 `dashboard.ops_overview` 同源）
- 分桶在 Python 做（`normalize_event_time` + 手写分桶），不用 SQL 日期函数 —— 库里的时间既有裸 CST 串
  又有 UTC ISO，SQLite/MySQL 日期函数还不通用（踩过的坑，勿改回 SQL 分桶）
- 响应字段：`kpis{queue_depth,success_rate,p95_duration_s,engines_online,engines_total,tokens}`
  + `charts{task_outcome,token_trend,model_share}` + `scope{repo,repos,restricted}`

### 前端
- 图表库 **ECharts 5.6.0 本地 vendored** → `src/api/static/vendor/echarts.min.js`（1.0MB）+ 同目录 `echarts.LICENSE`
  （Apache-2.0）+ `README.md` 记来源与 sha256；**不走 CDN**
- 总览分区：KPI 5 卡（排队/成功率/P95/在线引擎/Token）+ ① 任务量与结果（堆叠柱 + 成功率右轴）
