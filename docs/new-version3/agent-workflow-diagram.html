Grape 多 Agent 执行交互流程图

Issue 驱动 · A2A 交棒 · 阶段矩阵路由 · 异步执行

触发
⚡
Webhook 事件触发
GitCode Issue/PR → grape webhook → event_pipeline 路由
issue_opened → 路由到 vod（阶段矩阵初始化）
issue_comment → 按 issue_state.stage 路由到当前阶段 Agent
pull_request_merged → 按 issue_state.stage 路由（通常 → sre）
A2A API 调用 → 直接路由到指定 Agent
issue_opened
Phase 1: 需求收集
V
VOD Agent — skill: vod
职责：从开发者声音中收集反馈、聚类分析、提炼价值
动作：需求收敛为清晰后 → Issue 评论 → A2A 交棒 issue
A2A 交棒 → issue
curl -X POST /api/a2a -d '{"agent":"issue", "payload":{"repository":"...", "issue_number":"9", "context":"需求已收敛，请分类指派"}}'
A2A → issue
Phase 2: Issue 运营
I
Issue Agent — skill: issue-advance
职责：深度可开发性分析 → 分类/标签/分配 → Spec 生成
动作：评级 ready → 生成 Spec → 打 spec-ready 标签 → A2A 交棒 coding
回退：需求不清晰 → A2A 交棒 vod 澄清
A2A 交棒 → coding
curl -X POST /api/a2a -d '{"agent":"coding", "payload":{"repository":"...", "issue_number":"9", "context":"Spec 已生成，请开始开发"}}'
A2A → coding
Phase 3: 代码实现
C
Coding Agent — skill: implementation / skill-creator
职责：代码实现 + 创建 PR + 自测
动作：读 Spec → 实现 → 自测 → 创建 PR → Issue 评论 → A2A 交棒 qa
失败：无法实现 → Issue 评论说明原因，不创建 PR，不交棒
A2A 交棒 → qa（携带 pr_number）
curl -X POST /api/a2a -d '{"agent":"qa", "payload":{"repository":"...", "issue_number":"9", "pr_number":"7", "context":"PR#7 已提交，请测试验证"}}'
A2A → qa（携带 PR）
Phase 4: 测试验证
Q
QA Agent — skill: pr / skill-tester
职责：代码审查 + 功能测试 + 安全扫描
通过：合并 PR → A2A 交棒 sre 发布
失败：A2A 回 coding 修复（携带审查意见）
✅ 测试通过
A2A → sre
curl -X POST /api/a2a -d '{"agent":"sre", "payload":{"repository":"...", "issue_number":"9", "context":"测试通过，PR已合并，请发布"}}'
🔴 测试失败
A2A 回 → coding
curl -X POST /api/a2a -d '{"agent":"coding", "payload":{"repository":"...", "issue_number":"9", "pr_number":"7", "context":"审查发现 Critical 问题，请修复"}}'
A2A → sre（测试通过）
Phase 5: 部署发布
S
SRE Agent — skill: cloud-deploy / skill-publish
职责：构建部署 + 发布管理 + 监控运维
动作：部署/发布 → Issue 评论告知结果 → 流程结束（issue_state → done）
完成
结束
Issue 关闭 — issue_state.stage = done
任务执行机制（每次 A2A 交棒时发生）
1. 鉴权：仓库 bot token 校验
2. 创建 event：status=running，记录到 events 表
3. 查 session：devops_agent_session 获取绑定的 skill + runtime
4. 组装 prompt：SKILL.md + Issue 上下文 + A2A context
5. 物化文件：skill → .skills/，知识库 → .project-info/
6. 注入环境变量：BOT_TOKEN、AK/SK、PR_NUMBER、ISSUE_NUMBER
7. 选引擎执行：专属 → 全局 → 本机
8. 完成：更新 event status=completed + result_text
9. 交棒：Agent 调 A2A API 触发下一个 Agent
Agent 间信息传递载体
A2A context：上一个 Agent 的结论和建议下一步（prompt 里注入）
Issue 评论：执行结果公开记录（所有 Agent 和用户可见）
PR 评论：测试报告、审查意见
issue_state.stage：当前阶段（vod/issue/coding/qa/sre/done），决定事件路由
project_info_files：项目知识库（repo-credentials.json 等）随任务物化
env_extra：环境变量凭据（AK/SK、BOT_TOKEN）
