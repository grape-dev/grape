# 需求文档：场景&技能

> 关联 Issue：grape-dev/grape#11
> 状态：需求已确认

## 一、为什么要做

当前 DevOps 技能页面把所有技能平铺在一起，开发者面临三个问题：

1. 不知道哪个技能好——没有推荐、没有评价，只能靠名称和一句话描述猜
2. 不知道技能能解决什么问题——没有场景介绍，看不出技能之间怎么配合
3. 查阅困难——38 个技能铺一屏，找东西靠搜索，没有分类引导

参考 WorkBuddy 的技能市场和专家市场，希望让开发者像逛应用市场一样浏览场景和技能。

## 二、用户是谁

- 新用户：还没有托管仓库，想了解 grape 能做什么、有哪些开发模式
- 开发者：已有仓库，想找到合适的技能提升效率
- 仓库管理员：已托管仓库，想给仓库换一个开发场景

## 三、菜单结构

### 当前菜单

```
工作区：任务中心 / 场景中心 / 流水线
DevOps Agents：VOD / Issue / Coding / QA / SRE
知识库：DevOps 技能 / 项目知识库
设置：通用设置 / GitCode 仓库 / Agent 运行时 / 系统监控
```

### 调整后

```
工作区：任务中心 / 场景中心 / 流水线
DevOps Agents：VOD / Issue / Coding / QA / SRE
DevOps 市场：场景市场 / 技能市场
知识库：项目知识库
设置：通用设置 / GitCode 仓库 / Agent 运行时 / 系统监控
```

调整说明：
- 新增"DevOps 市场"一级菜单，包含"场景市场"和"技能市场"两个页面
- 原"知识库"组下的"DevOps 技能"移到"DevOps 市场"下并重设计
- 原"知识库"组只保留"项目知识库"
- 原"场景中心"不动，它是仓库级操作页面，和"场景市场"定位不同

### 场景市场 vs 场景中心

这两个页面名字像但职责完全不同，需要明确区分：

| | 场景中心（现有，不动） | 场景市场（新） |
|--|--|--|
| 给谁用 | 已有仓库的用户 | 所有用户 |
| 做什么 | 对当前仓库配置/编辑场景 | 浏览官方场景、了解功能、一键体验 |
| 举例 | 我有个仓库，要给它配 IaC 开发流程 | 我想了解 grape 有哪些开发模式，先体验一下 |

## 四、场景市场

### 4.1 页面结构

页面顶部有 tab 切换：「场景」「技能」，默认进场景。

场景市场页面从上到下：

1. 搜索框 + 查询按钮（按场景名称/功能介绍过滤）
2. 精选场景区域（置顶，带 🌟 标记的场景，横向滚动）
3. 全部场景区域（分类 tab 切换 + 网格布局，场景卡片）

分类 tab（按场景类型过滤）：
- 全部 / 移动开发 / 通用 / 基础设施 / 技能开发 / AI 应用 / 内容创作

### 4.2 场景卡片

每个场景卡片展示：

- 顶部色条：场景分类的渐变色标识
- 场景图标：场景的视觉标识（emoji）
- 场景名称：如"通用开发"、"IaC 开发"、"博客发布"
- 精选徽章：精选场景显示 🌟
- 功能介绍：2-3 句话描述这个场景适合什么场景、解决什么问题
- 包含技能：列出这个场景用到的技能名称链路（如 VOD → Issue → Coding → QA → SRE）
- 技能数 + 在用仓库数（如"5 技能 · 5 仓库在用"）
- 两个按钮：「应用」「体验」
- 点击卡片本身（非按钮区域）→ 进入场景详情页

### 4.3 场景详情页

点击场景卡片进入场景详情页，展示更完整的信息：

- 场景大图标 + 场景名称 + 精选徽章 + 完整功能介绍
- 执行流程图：横向卡片 + 箭头展示技能链路，每个技能卡片含编号、Agent 标签、技能名称、角色描述、输入/输出/产出
  - 技能名称可点击跳转到技能市场对应技能详情
- 技能套件：纵向列表展示每个技能的编号、Agent 标签、名称、角色描述、输入/输出/产出
  - 技能名称可点击跳转到技能市场对应技能详情
- 样例模板：该场景关联的最佳实践模板项目（名称、描述、语言、stars）
- 在用仓库列表：当前正在使用该场景的仓库名称列表
- 「应用」「体验」按钮

### 4.4 "应用"操作

用户点击「应用」按钮：

- 前提：用户已选中一个已托管仓库
- 行为：把这个场景应用为当前仓库的开发场景
- 成功：提示"场景已应用"，仓库的 Agent 配置切换为该场景的技能组合
- 未选仓库：提示"请先选择一个仓库"

### 4.5 "体验"操作

用户点击「体验」按钮：

- 行为：自动基于该场景关联的模板项目创建一个新项目
  1. 自动创建 GitCode 仓库
  2. 自动写入模板代码
  3. 自动托管到 grape
  4. 自动应用该场景
  5. 自动进入新项目页面
- 限制：每个用户每个场景只能体验一次
  - 已体验过 → 直接跳转到之前创建的体验项目
  - 未体验过 → 创建新项目并跳转
- 目的：让用户零门槛快速感受场景效果

### 4.6 当前官方场景清单

| 场景 | 名称 | 包含技能 |
|------|------|---------|
| default | 通用开发 | vod → issue-advance → implementation → pr → cloud-deploy |
| cloud-native | 云原生开发 | vod → issue-advance → implementation → pr → cloud-deploy |
| iac | IaC 开发 | iac-vod → iac-issue → iac-coding → iac-qa → iac-sre |
| agent-dev | Agent 开发 | vod → issue-advance → implementation → pr → cloud-deploy |
| skill-dev | 华为云 Skill 开发 | vod → skill-issue → skill-creator → skill-tester → skill-publish |
| api-skill-dev | 通用 Skill 开发 | vod → skill-issue → rest-api-skill-creator → rest-api-skill-tester → skill-publish |
| blog-publish | 博客发布 | blog-vod → blog-issue → ai-blog-generation → blog-publish |

## 五、技能市场

### 5.1 页面结构

点「技能市场」tab 进入，页面从上到下：

1. 搜索框 + scope 页签（官方 / 仓库 / 个人）+ 查找技能按钮 + 最新/最热排序按钮 + 上传技能按钮（仓库/个人页签显示）
2. 场景与技能关系说明（提示框，解释两者关系）
3. 精选技能区域（置顶，带 🌟 标记的官方技能，按点赞数排序，横向滚动）
4. 全部技能区域（Agent 类型 tab 切换 + 计数，按 Agent 分组：VOD / Issue / Coding / QA / SRE / Chat）

### 5.2 场景与技能关系说明

在技能市场页面顶部（提示框形式）放一段简短说明，帮助新用户理解场景和技能的关系：

- 场景是多个技能按开发流程组合的开发模式（如 VOD→Issue→Coding→QA→SRE）
- 技能是单个 Agent 的能力包，完成具体动作（如代码实现、PR 审查）
- 简洁表述，不占过多空间，如提示框或一行说明文字

### 5.3 技能卡片

每个技能卡片展示：

- Agent 图标：卡片标题前展示 Agent 类型图标（如 VOD 🔍、Issue 📋、Coding 💻、QA 🧪、SRE ⚙️，复用 _AGENT_TYPES 配色）
- Agent 类型标签：彩色小标签（如 VOD 蓝色、Issue 红色、Coding 青色）
- 技能名称：如"代码实现"、"PR 管理"
- 精选徽章：精选技能显示 🌟（仅官方技能）
- 描述：2-3 行，说清楚这个技能能做什么、解决什么问题
- 点赞按钮 + 数量：❤️ 图标 + 数字，点击即点赞，再点取消
- 所属场景：展示该技能出现在哪些场景中（如"通用开发、IaC 开发"），点击可跳转到场景市场对应场景
- 使用统计：展示该技能被多少个场景使用、被多少个仓库间接使用（如"3 个场景在用，8 个仓库在用"）
- 「查看详情」按钮
- 「上传技能」按钮（仓库/个人页签下显示）
- 「删除」按钮（仓库/个人页签下显示）
- 「转为仓库技能」按钮（个人页签下显示）

### 5.4 技能使用统计

技能卡片上除了点赞数，还展示使用统计：

- 被多少个场景使用：统计该技能出现在多少个 official 场景的 nodes 中
- 被多少个仓库间接使用：统计使用该技能的场景被多少个仓库应用（managed_repos.dev_scene）
- 数据来源：后端从 devops_pipeline_scene.nodes_json + managed_repos.dev_scene 联合统计
- 展示形式：卡片底部小字（如"3 个场景在用，8 个仓库在用"），和点赞数并排

### 5.5 技能查找

参考 WorkBuddy 的"查找技能"功能：

- 入口：搜索框旁边的"查找技能"按钮（复用搜索框，不单独弹窗）
- 行为：用户在搜索框输入任务描述（如"我想自动化部署一个 Flask 应用"），点击"查找技能"按钮
  - 输入内容能匹配技能名称时 → 按名称过滤（和普通搜索效果一致）
  - 输入内容匹配不到技能名称时 → 按任务描述关键词匹配技能 description，推荐相关技能
- 展示：匹配结果直接在全部技能区域展示，每个技能卡片下方显示匹配关键词
- 目的：让不知道该用什么技能的用户，通过描述任务找到合适的技能

### 5.6 点赞

- 每个登录用户可以对每个技能点赞或取消点赞
- 点赞后按钮变实心 ❤️，取消后变空心 🤍
- 精选区域按点赞数从高到低排序
- 同一个技能同一用户只能点赞一次

### 5.7 精选技能

- 精选范围：仅官方技能
- 精选标记通过配置文件维护（和现有技能同步机制一致）
- 精选技能在页面顶部独立展示（横向滚动）
- 精选区域同时展示点赞数，方便用户判断受欢迎程度

### 5.8 现有能力保留

以下现有功能全部保留，不做删减：

- **上传技能**：在仓库/个人页签下，点击「上传技能」按钮弹出上传弹窗（选 agent_type → 上传 ZIP → 校验 → 存储）
- **删除技能**：仓库/个人页签下，技能卡片上的「删除」按钮（现有逻辑不变）
- **转为仓库技能**：个人页签下，个人技能可转为仓库技能（现有逻辑不变）
- **下载技能模板**：上传弹窗中的「下载模板」链接（现有逻辑不变）
- **下载技能包**：技能详情页的「下载技能包」按钮，OBS 模式返回临时签名 URL（现有逻辑不变）
- **技能详情页**：点击「查看详情」进入，展示 SKILL.md 全文、技能信息（现有功能不变，新增点赞和所属场景）
- **华为云技能包**：huawei-cloud 技能的子技能卡片展示（现有逻辑不变）
- **官方技能同步**：进入官方页签时自动检查并同步新增技能（现有逻辑不变）

### 5.9 技能详情页

点击「查看详情」进入技能详情页：

- 左右两栏布局：左栏 SKILL.md 预览，右栏技能信息面板
- 技能名称、Agent 图标、scope 标签、精选徽章
- 描述
- SKILL.md 全文内容
- 下载技能包按钮（OBS 模式返回临时签名 URL）
- 点赞数 + 精选标识（新增）
- 所属场景标签，点击可跳转到场景市场对应场景详情（新增）

## 六、交互流程

### 6.1 新用户探索流程

```
用户打开 grape
→ 点击"DevOps 市场" → "场景市场"
→ 看到精选场景（如"通用开发"🌟）
→ 点击场景卡片进入详情，了解完整功能介绍和技能链路
→ 返回列表，点击「体验」
→ 系统自动创建项目+托管+应用场景
→ 自动跳转到新项目，用户开始体验
→ 体验后想了解技能
→ 点击"DevOps 市场" → "技能市场"
→ 浏览精选技能，点赞感兴趣的
→ 查看技能组合场景介绍，理解技能怎么配合
→ 或点击"查找技能"，输入任务描述让系统推荐
→ 点击「查看详情」了解技能能力
```

### 6.2 已有仓库用户应用场景

```
用户选中一个已托管仓库
→ 点击"DevOps 市场" → "场景市场"
→ 搜索或浏览场景列表，对比功能介绍
→ 点击场景卡片查看详情
→ 点击「应用」
→ 仓库场景切换完成
→ 回到"场景中心"查看/微调配置
```

### 6.3 开发者查找技能

```
用户有具体任务但不知道用什么技能
→ 点击"DevOps 市场" → "技能市场"
→ 点击"查找技能"
→ 输入任务描述（如"我想自动化部署一个 Flask 应用"）
→ 系统推荐相关技能列表
→ 点击推荐技能查看详情
→ 了解技能能力后，在场景中心把它配到仓库的场景中
```

### 6.4 开发者管理自己的技能

```
用户点击"DevOps 市场" → "技能市场"
→ 切换到"个人"页签
→ 点击「上传技能」上传新技能
→ 或对已有技能点击「转为仓库技能」共享给团队
→ 或点击「删除」清理不需要的技能
→ 切换到"仓库"页签管理仓库级技能
```

## 七、需求讨论记录

### 讨论一：菜单命名和归属

- 原方案提出"技能市场"作为一级菜单名，用户反馈 Issue 原文写的是"场景&技能"
- 讨论过程中又觉得"场景&技能"不够直觉，最终确定分组名为"DevOps 市场"
- 结论：一级菜单命名"DevOps 市场"，下设"场景市场"和"技能市场"两个子页面
- 讨论过程：
  - 最初考虑把技能留在"知识库"下，但技能不是知识（是可执行能力包），放在知识库下逻辑不通
  - 考虑过合并进现有"场景中心"，但场景中心是仓库级操作页面，场景市场是发现/浏览页面，职责不同不能合并
  - 考虑过新增"资源市场"作为一级菜单名，最终采用 Issue 原文的"场景&技能"

### 讨论二：场景市场 vs 场景中心

- 用户明确指出两个页面职责不一样，不能合并
- 场景中心（现有）：用户配置面，对已托管仓库选/编辑/应用场景
- 场景市场（新）：发现面，浏览官方场景介绍、一键体验、一键应用
- 结论：两个页面独立共存，场景中心不动，场景市场新建

### 讨论三：场景要不要点赞

- 分析了点赞对场景的含义：技能点赞=能力好用，场景点赞=流程好用？语义不够清晰
- 场景更适合展示"在用仓库数"（从 managed_repos.dev_scene 统计），体现流行度
- 结论：场景用"在用仓库数"替代点赞，技能保留点赞

### 讨论四：WorkBuddy 专家市场要不要参考

- WorkBuddy 有"专家中心"（角色切换+协作执行）和"技能市场"两个独立功能
- grape 没有"专家/角色"概念，Agent 类型（VOD/Issue/Coding/QA/SRE）已经是角色划分
- 结论：不引入专家概念，参考 WorkBuddy 技能市场的精选/推荐/搜索/查找能力

### 讨论五：技能组合场景介绍

- Issue 原文要求"增加场景的介绍，例如技能组合场景的介绍"
- 场景市场已有场景卡片（从场景角度展示技能组合），但技能市场本身缺少从技能角度的场景组合介绍
- 结论：在技能市场页面增加"技能组合场景介绍"区域，展示场景的技能链路+每个技能的角色说明，与场景市场形成互补

### 讨论六：现有能力保留

- 用户明确指出：上传/删除/转仓库等现有功能必须保留
- 结论：现有技能管理能力全部保留不做删减，新功能（精选/点赞/场景介绍/技能查找）是增量

### 讨论七：场景卡片点击行为

- 确认：点击场景卡片本身（非按钮区域）进入场景详情页
- 场景详情页展示：完整功能介绍、技能链路详解（每个技能的角色说明）、关联模板列表、在用仓库列表
- 技能链路详解中的技能名称可跳转到技能市场对应技能详情

### 讨论八：技能详情页增强

- 确认：技能详情页在现有基础上增加点赞按钮+数量、所属场景标签（可跳转）

### 讨论九：精选范围

- 确认：精选标记先只针对官方技能，仓库技能和个人技能暂不支持精选

### 讨论十：场景市场搜索

- 确认：场景市场要支持搜索（按场景名称/功能介绍过滤）

### 讨论十一：技能查找功能

- 确认：参考 WorkBuddy 的"查找技能"，用户输入任务描述自动推荐相关技能
- 第一期需要做

### 讨论十二：技能组合场景介绍（已取消）
