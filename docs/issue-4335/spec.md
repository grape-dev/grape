# Spec: Issue #4335 — issues update 传 body 被 409 一致性断言误拦（主语判定误伤）

> 承接前序流水线 Spec（Issue 评论 203588197），开发基线 `weekly-mys`。

## 目标
修正 `issues update` 发布前一致性断言（release_guard）的「正文主语」提取规则：
正文中对其他 Issue 编号的合法样例引用不再被误判为主语触发 409，原始正文可正常回填；
真实主语不一致（正文确实以其他 Issue 为陈述对象）仍被拦截。

## 现状缺陷
- `first_issue_anchor` 在全部非引用行中取**首个**显式 `Issue #N` 作为主语——用户反馈类
  Issue 正文（如 #4334 任务回填含 `Issue #3888` 样例引用的正文）里第一个命中的往往是
  描述文字中的样例编号，而非正文主语，导致 update 传 body 被 409 误伤。
- 仅更新 labels/assignee（不传 body）不受影响，行为必须保持不变。

## 规则（收窄后的主语判定）
主语锚点仅在以下「主语位置」判定，正文段落内其余引用一律视为样例引用（白名单）：
1. **开头行**：首个非空、非引用行（正文的主题句/标题）内的 Issue 引用；
2. **标题行**：markdown 标题行（`#` 开头）内的 Issue 引用。

同时保留既有防线并与评论侧 PR #2150（#4329）对齐（共用实现，不分叉）：
- 引用行（`>` 开头，含嵌套）跳过——他号正文摘录不作主语；
- 「段名#序号」链路引用（`vod#25105` 等）先剔除再找锚点（#4257）；
- 主语锚点正则采用 #4329 的词元/路径边界（`(?<![A-Za-z0-9_/.])` /
  `(?![A-Za-z0-9_])`），`issueNNN_*` 样例前缀、`test_issueN_*.py` 文件名/路径不算主语；
- update 侧与评论侧（comments create/update）共用同一 `first_issue_anchor`
  「主语提取器 + 样例白名单」实现，409 保留，不降级放行。

## 验收标准
- [ ] 正文含其他 Issue 编号样例引用（含「」内错误消息引用）时 update 传 body 不再 409；
- [ ] 不传 body（labels/assignee-only）行为不变；
- [ ] 真实主语不一致（开头行/标题行指向其他 Issue）仍 409 拦截；
- [ ] update 侧与评论侧共用同一提取器，回归测试覆盖两类样例 + 真实拦截样例。
