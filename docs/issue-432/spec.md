# Spec: Issue #432 — Agent 运行时引擎搜索过滤后展示引擎总数

> Generated by Coding Agent | 2026-10-22

## Objective
Agent 运行时（Runtimes）页面 Engines/Workers 统计栏在健康分布最前展示「共 N 台」；基础项已由 bf2a00c45 实现，本次聚焦两处残留缺口：
1. **口径一致性**：Engines tab 前端过滤（搜索/场景/标签）后统计栏不刷新——统计栏统计未过滤的 `data.runtimes`，而 `renderEngines()` 使用前端过滤后的 `filtered` 列表。
2. **i18n**：统计栏 5 项文案（共/在线/刚失联/离线/待回收）为中文硬编码，未走 i18n。

## Scope (In)
- `src/api/static/js/pages/runtimes.js`
  - 提取共享过滤函数 `_filterEngines(runtimes)`，供 `renderEngines()` 和 `_summaryStatsBar()` 共用。
  - `_summaryStatsBar()`：Engines tab 改为统计过滤后列表；Workers tab 维持 `devices` 口径不变。
  - 统计栏 5 项文案全部改走 i18n：`runtimes.stats.total`（含 `{count}` 插值）、健康 4 项复用 `runtimes.health.*` key。
  - 空态（列表为 0）维持现有行为：统计栏不渲染（`return ''`）。
- `src/api/static/locales/zh/runtimes.json`、`src/api/static/locales/en/runtimes.json`
  - 新增 `stats.total` key（zh：`共 {count} 台`；en：`Total {count}`），保持两语言包 key 结构一致。

## Scope (Out)
- 分页总条数「共 N 条 / N 页」（`_paginationBar`）不改动。
- 后端接口与分页控件不改。
- Workers tab 筛选由后端处理，无前端过滤口径问题。

## Technical Approach
- 提取 `renderEngines` 内 filter 谓词为独立函数 `_filterEngines(runtimes)`，返回过滤后数组（不含排序）。
- `renderEngines` 调用 `_filterEngines` 后再排序；`_summaryStatsBar` 在 engines tab 调用 `_filterEngines` 取过滤后列表做统计。
- 文案改 `I18N.t('runtimes.stats.total', {count: N})` 和 `I18N.t('runtimes.health.online')` 等，按既有 `{count}` 插值约定。

## Acceptance Criteria
- Engines tab「共 N 台」= 过滤后条数 = 在线+刚失联+离线+待回收之和
- Workers tab 同样显示「共 N 台」（devices 口径不变）
- 搜索/类型/scope/场景/标签筛选及清除后统计正确刷新
- 中英文文案均正常，无中文硬编码残留
- 空态（0 台）统计栏不渲染
- 现有测试全过 + 新增测试覆盖
