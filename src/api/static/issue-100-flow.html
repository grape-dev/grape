Issue #100：清理位置
新增
DELETE /api/events/{seq}/chat（新增）
清理范围：
- event_thread 表 WHERE anchor_seq=seq → 删除所有对话消息（user/agent/system）
- 包括 📌 知识沉淀留痕 和 🔄 流程操作留痕（都是 system 消息）
不删：
- 知识文件（knowledge.md / issues/{n}/knowledge.md）→ 独立沉淀，有独立删除入口
- agent_shared_knowledge / scene_knowledge_ref 记录 → 知识库管理
- events 表记录 → 事件本身不删
清理后：loadConversation() 刷新 → messages 为空 → 对话面板显示提示，对话产出面板流程操作为空
↓
新增
前端清理入口（新增）
对话面板标题栏（convPanel h3）加"清理"按钮
点击 → 确认气泡（复用 Chat Agent 的 chat-del-overlay 样式）
确认 → DELETE 请求 → loadConversation() 刷新
数据表关系
表用途Issue #100 清理
events事件记录（seq/repo/agent/result/status）不删
event_thread对话消息（anchor_seq 关联事件）删除 WHERE anchor_seq=seq
agent_shared_knowledge知识索引（文件路径/obs_key/source）不删（独立沉淀）
scene_knowledge_ref知识关联（scene/agent/issue）不删
工作区文件knowledge.md / issues/{n}/knowledge.md不删
关键区分：event_thread 里的 📌/🔄 system 消息只是留痕（通知用户 agent 做了什么操作）， 真正的知识数据存在工作区文件 + agent_shared_knowledge 表。 清理对话只删留痕，不删知识本身。 清理后对话产出面板的"知识沉淀"区域仍有内容（从 knowledge 对象读，独立于 messages）。
